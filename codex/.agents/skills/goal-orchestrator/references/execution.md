# 執行協定

只在派工、前台操作、模型解析、Goal 恢復或驗收證據需要細節時讀本檔；核心分工與錯誤規則以 `SKILL.md` 與根目錄 `SPEC.md` 為準，不在此重述。

## Goal 狀態

保存：原始目標、最新核准變更、驗收標準、目前階段與停止點；模型鎖定；工作包負責者、依賴、來源版號／雜湊、狀態、錯誤次數、目前推理、成果與證據位置；每批並行派工的範圍比對結果；主線自做的步驟與理由。狀態是快照不是日誌：目前階段只寫一兩行，每個工作包收口都補一列判定紀錄，已完成的工作包搬到封存檔，讓狀態檔維持在每次派工前都讀得起的長度，並更新最後更新時間。恢復時只讀狀態、必要來源與未解差異；來源與驗證條件未變的有效證據不重跑。

## 模型解析

查目前主機明列的模型、產品定位、正式發布世代、必要模態與支援推理層級；只依可核對的當前資料判定。預設不納入第三方或影像、語音、即時、資安等專用模型。選定後記錄角色、具體模型、基準推理、證據與時間。

「升一檔」是在同一鎖定模型的已知支援層級中移到緊鄰較高值；不可為升檔換模型或以相同值冒充。若無更高層級或無法要求該值，停止重派、揭露原因並由主線提早接手該包。模型不可用時可重解析，但保留工作包錯誤次數；無合格模型／必要能力則記執行問題，不靜默降級。

## 工作包

每包只負責一類工作，至少包含：

- `id`、類型（A 查核／B 技術／介面操作）、負責者、依賴、錯誤次數、模型與推理。
- 問題、必要來源與精確範圍、候選版號／雜湊、客觀判準。
- 可修改範圍、共用資源（會觸碰的套件／lockfile、全域編號、開發伺服器／資料庫／測試資料／帳號、瀏覽器工具）、資料副作用、禁止事項、隔離／還原方式。
- 回報格式：結論、實際覆蓋、發現與影響、證據位置、未查項目及原因。

每包的 prompt 先存成檔（Goal 狀態旁 `wp/<id>.md`），再派工；重派與恢復都從檔案讀。

**並行派工閘**：同一批要並行的工作包，加上所有在途工作包，逐項比對「可修改範圍」與「共用資源」——檔案路徑（含 `**`／`*` 前綴涵蓋）、資料表、全域編號、套件／lockfile、共用服務、測試資料、帳號、瀏覽器工具。任一項出現在兩包以上即為交集：把後派的一包加依賴改依序，或把共用項改到唯一一包、另一包 prompt 明寫「不改該項，需要時寫進回報待決」。可直接跑 `python3 scripts/scope-overlap.py wp/<本批>.md … --in-flight wp/<在途>.md …`（exit 0 無交集、1 有交集並列出、2 缺「可修改範圍」段；共用資源用 `鍵:值` 寫法，如 `瀏覽器:playwright`、`套件:安裝`、`migration:134`、`服務:3300`、`帳號:ceo`，同名即交集）。比對結果（批次、包 id、交集清單或「無」）記入 Goal 狀態後才派出；派出後新增的工作包，比對對象包含所有仍在途者。

只傳完成工作所需的最小上下文；重派只增加主線指正、更新來源／期望與可復用成果。主線完整閱讀回報，核對直接來源、實際影響路徑與候選版本，不把未查項目視為通過。

## 前台操作案例

每案寫明：URL／版本、帳號角色與起始狀態、測試資料、瀏覽器／尺寸、使用者工作、操作步驟、各節點預期、允許副作用與還原、禁止操作、必留證據。功能回歸可給明確步驟；自然旅程只給起始狀態、目標、成功條件與禁止事項，不提示控制項位置。

子代理須以真實點擊、輸入、選擇、拖拉或切換完成路徑；不得以狀態注入、內部 API、DOM 或 OCR 取代操作／視覺證據。畫面或狀態改變後重新讀取介面；空白或異常截圖不算證據。回報 `PASS`、`FAIL` 或 `BLOCKED`，附實際步驟、結果、期望差異與未測範圍。

使用新開且可隔離的測試分頁／資料。付款、刪除正式資料、對外發送、身分驗證、個資、憑證或正式環境不可逆操作，未獲明確授權就停在操作前。產品 FAIL 修正後，重測受影響案例與既定必要回歸。

## 並行與完成

依依賴並行，且每批先過「並行派工閘」；共享檔案、瀏覽器、帳號、資料庫或測試資料無法隔離時排程。介面子代理若共用同一個瀏覽器工具或登入狀態，一次只跑一個；要並行就各自用隔離的瀏覽器程序，並在工作包共用資源欄寫清楚。查核期間候選版被修改，受影響證據失效。

只在原始 Goal、核准變更與適用驗收全部有同版有效證據時完成。必要決策、授權或外部依賴未解時，繼續其他已授權工作並如實停在等待／阻塞，不把階段候選或部分 PASS 當整體完成。
