# 行為案例（Codex 驗證對照）

| # | 案例 | Codex 驗證方式 |
|---|---|---|
| 1 | 網頁含視覺與互動／後端時走 A＋B；純靜態頁只走 A。 | sidecar 工作包同時有 A、B；純靜態頁只有 A。 |
| 2 | A 子代理只做客觀查核，不改成品或判定風格。 | 子代理回報只有發現與證據；沒有設計修改。 |
| 3 | B 子代理實作；錯 3 前主線不接手程式修改。 | B 包錯誤次數小於 3 時，主線只查核、執行既有指令或維護 sidecar。 |
| 4 | 介面代理用真實事件蒐證；產品 FAIL 退回 B。 | 介面包錯誤次數不因產品 FAIL 增加。 |
| 5 | 品質錯 1、2 升一檔重派；錯 3 主線接手；沒有更高推理檔時只阻塞，不提前接手。 | sidecar 顯示同模型相鄰推理檔次；無升檔能力時保留錯誤次數並記 BLOCKED；錯 3 後無第四次重派。 |
| 6 | 執行問題不占品質錯誤。 | BLOCKED 紀錄不改錯誤次數與推理檔。 |
| 7 | 不同候選版證據不得拼接 PASS。 | 最終證據的候選版／雜湊一致。 |
| 8 | 修改範圍或共用資源重疊不得並行。 | `scope-overlap.py` exit 0 與結果已登記後才並行派工。 |
| 9 | 同一瀏覽器工具或登入狀態不得並行。 | 同時在途的介面包使用隔離工具與不同帳號。 |
| 10 | 子代理不做未授權套件、lockfile、服務或全域編號變更。 | 回報 BLOCKED 或品質錯誤，未污染其他工作包。 |
| 11 | 壓縮、續接或恢復後先重載技能與狀態。 | 下一次派工前依序讀技能、執行協定、原生 Goal 與精確匹配的 sidecar。 |
| 12 | 主線自做只限確定性操作且登記理由。 | sidecar「主線自做」有紀錄；錯 3 前不改 B 原始碼。 |
| 13 | 新工作包從基準投入開始。 | 第一次派工為一般 Medium、介面 Low；高檔只在品質錯誤後出現。 |
| 14 | 找 X／確認沒有 X 先枚舉候選全集。 | 候選全集早於深入驗證；結論含候選／已驗／未驗數；UI 用真實操作畫面，程式碼／檔案／DB／API 用各自的原生端到端查核結果。 |
| 15 | 主線低於最低能力時不建立狀態或派工。 | 除非使用者明確沿用，回覆只揭露差距並等待切換。 |
| 16 | Goal 與 sidecar 職責分開。 | 原生 Goal 管目標／狀態／預算；工作包、錯誤次數、證據只寫 sidecar。 |
| 17 | 主線不宣稱已切換模型或推理。 | 實際主線不符時只揭露差距；sidecar 記實際值。 |
| 18 | 子代理不做 Git 寫入、正式規格變更或對外發送。 | 指令停在操作前並回報主線，不視為已完成。 |
| 19 | 原生 Goal 與 sidecar 不會因最近修改時間而誤綁。 | 有 id 以 id 匹配；無 id 以 objective 原文與 SHA-256 匹配；多個未完成且無精確匹配時要求使用者指定。 |
| 20 | 動態模型解析不靠名稱猜測。 | 依 session／主機實際資訊、主機模型目錄、官方 OpenAI 文件依序解析；都無法核對時記 BLOCKED。 |
| 21 | 研究／系統規劃走 C 線；主線作取捨與正式文件，子代理只交研究包。 | sidecar 有研究範圍、截止時點、來源與反證；子代理回報不含最終系統決策或正式文件修改。 |
| 22 | 共用資源只記實際正值，禁止值不製造假衝突。 | `scope-overlap.py` 不會把 `.worktrees` 誤切為 `.worktree`；`不安裝`、`不使用`不算衝突，相同的正值 worktree／帳號仍 exit 1。 |
| 23 | 並行 B 技術包使用同 base commit 的隔離 worktree，整合後才成為 canonical candidate。 | 工作包有 `[工作區]` 與獨立 `worktree:<id>`；子代理不操作 Git，主線核對實際變更後在單一候選版跑整合回歸。 |
| 24 | sidecar 是快照，超過上限時先封存才派新包。 | `sidecar-guard.py` 在 150 行內 exit 0；151～180 行提醒；超過 180 行 exit 1，active／BLOCKED／當前候選版仍留在 `state.md`。 |
| 25 | 長任務出現待決事項時不阻塞整條主線：已確認範圍內的可逆事項採推薦選項；不可逆、付費、憑證、對外發送與上層規則要求事前確認的動作只阻塞該動作；只有無任何可執行工作時才在回合結尾一次列出待決清單。 | sidecar 「待決清單」有「已採預設」與改回方式，其後仍有派工、整合或驗證記錄；BLOCKED 的單一動作沒有越權執行；同一事項不重問。 |
| 26 | 通過並行閘的已就緒工作包會立即填滿當下可用子代理席位；任一包完成就補派新解鎖工作，不等整批收齊；主線同時進行整合與驗證。 | 有多個互斥已就緒包時，同一輪派工數等於當下可用席位與已就緒包數的較小值；完成通知後的下一個動作是收回、更新 sidecar 與補派，除非 sidecar 記錄只有一包就緒、真實依賴／衝突，或交接成本高於並行收益。 |
