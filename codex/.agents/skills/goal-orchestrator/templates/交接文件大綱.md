# 交接文件大綱（模板）

文件類成品照「事實表先行、只驗一次、不擋下游」做（規則見技能 SKILL 的文件類成品段）。這份大綱給每個任務直接套用：先做事實表，再寫完整說明 .md，最後從 .md 取材做流程圖、簡報與影片。

## 1. 事實表（寫 .md 之前）

開發驗收或部署完成、最後一次變更主機或設定之後，寫一支腳本一次讀出文件要用的值，輸出成 `事實表.md`：

```
# 事實表
讀取時間：2026-10-15 09:00（Asia/Taipei），讀取腳本：<腳本路徑>
| 編號 | 項目 | 值 | 出處（指令、檔名:行號或主機讀回） |
|---|---|---|---|
| F1 | 每日備份時間 | 08:00 | deployment/gateway-backup.timer:5 |
```

之後又改了主機或設定，就重跑腳本整批重讀，不手改單一值。

## 2. 完整說明 .md（唯一內容來源）

建議章節（照專案增減，標題就是出處對照表的 `md` 值）：

1. 專案概覽：解決什麼問題、解決方案一句話
2. 這個專案解決什麼問題
3. 解決方案簡介
4. 總體流程（把流程圖寫成文字：步驟、誰做、輸入輸出）
5. 細部流程（每個流程單元一節，同樣寫成文字）
6. 執行重點
7. 觀察重點
8. 預期結果
9. 部署與設定（數字一律取自事實表）
10. 例外處理與回退
11. 已知限制與待決事項
12. 交接清單
13. 問答與參考資料

寫法：每個數字、設定值、行號都要在事實表找得到；不寫開發過程與內部討論，只寫接手的人需要知道的事。

## 3. 出處對照表（做衍生件時同步記）

`出處對照.json`，每頁簡報、每句旁白一筆：

```json
[
  {"file": "簡報.html", "page": 2, "md": "## 這個專案解決什麼問題"},
  {"file": "旁白.txt", "sentence": 3, "md": "## 執行重點"}
]
```

.md 被退件修改時，查這張表找出受影響的頁與旁白句，只改那幾處。

## 4. 簡報（15 頁以內）

複製同資料夾的 `交接簡報模板.html`，把每個「（填入：…）」換成 .md 的內容，刪掉檔頭註解。模板已有：單一 HTML、離線雙擊可開、鍵盤（←、→、空白鍵、PageUp／PageDown、Home、End）與點擊換頁、頁碼、網址帶頁碼（例如 `簡報.html#4`）、第一頁的影片位置、超過 15 頁時頂端紅色提示。流程圖輸出成 PNG 放 `流程圖/` 子資料夾。

## 5. 概覽影片（5 分鐘以內，放簡報第一頁）

1. 旁白稿：從 .md 的「這個專案解決什麼問題、解決方案簡介、執行重點、觀察重點、預期結果」五節取句子，每段一個檔（`旁白01.txt`…），每句記進出處對照表。
2. 畫面：每段配一張圖（簡報截圖或流程圖 PNG）。
3. 合成（macOS 實測可用）：

```sh
say -v Meijia -f 旁白01.txt -o 旁白01.aiff
ffmpeg -y -loop 1 -i 畫面01.png -i 旁白01.aiff -c:v libx264 -tune stillimage -r 24 \
  -c:a aac -b:a 128k -pix_fmt yuv420p -vf "scale=1920:-2" -shortest 片段01.mp4
printf "file '片段01.mp4'\nfile '片段02.mp4'\n" > 片段清單.txt
ffmpeg -y -f concat -safe 0 -i 片段清單.txt -c copy 概覽影片.mp4
ffprobe -v error -show_entries format=duration -of csv=p=0 概覽影片.mp4   # 確認在 300 秒以內
```

## 6. 送驗前檢查

```sh
python3 <技能目錄>/scripts/doc-check.py --md 完整說明.md --facts 事實表.md \
  --derived 簡報.html 旁白01.txt 旁白02.txt --source-map 出處對照.json --keep 保留清單.txt --repo <專案根>
```

結束碼 0 才送驗。受監督時：.md 初稿連同事實表與這份輸出送一次，送出後立刻做簡報與影片；整包完成再送一次。
