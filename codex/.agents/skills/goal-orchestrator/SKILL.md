# Goal 長任務協作

本 adapter 實作根目錄 `SPEC.md`。只管理 Goal 的分工與續接。已有 Goal 就沿用；僅在使用者明確要求時建立 Goal 或設定 Token 預算。子代理不得建立或更動父 Goal。使用者最新明確指示與上層授權優先。上下文被壓縮、Goal 恢復或對話續接後，第一個動作是重讀本技能、執行協定與 Goal 狀態，再派工或判定；自動摘要不是規則來源。若 Goal 的完成條件只是任務描述、無法客觀判定，在第一則回覆給一句可判定的條件供使用者改設，使用者不改也照走。

## 分工與路由

任務可同時屬於 A、B；網頁預設 A＋B，只有完全無互動且無後端的純靜態頁只走 A。

| 工作線 | 主執行緒 | 子代理 |
|---|---|---|
| A 視覺／設計：網頁視覺、圖片、簡報、PDF | 設計、排版、風格判定、修正與最終驗收 | 解析素材／來源並客觀查核真實畫面的裁切、遮擋、溢出、可讀性、對齊、響應式與已鎖定規格；不改成品、不判定風格 |
| B 系統／技術 | 定義需求與驗收、拆包派工、查核證據、最終判定；僅同一技術包錯 3 後接手實作 | 一般子代理實作前端邏輯、後端、資料整合、修復與必要測試；介面子代理只按案例操作前台並蒐證 |

並行只限可修改範圍與共用資源都互斥的工作包：每個工作包宣告會觸碰的共用資源（套件／lockfile、migration 等全域編號、開發伺服器／資料庫／測試資料／帳號、瀏覽器工具）；每批派出前，主線逐項比對本批與在途工作包的可修改範圍與共用資源，結果記入 Goal 狀態；有交集就加依賴改依序或把共用項切給唯一一包，禁止事項互相點名不算隔離。同一個瀏覽器工具或登入狀態同一時間只派一個介面子代理。主線可自做確定性的操作型步驟（跑既有指令、起服務、查資料）並在 Goal 狀態登記理由；新增／修改程式或資料轉換邏輯一律派技術包。主線鎖定待驗候選版；視覺、互動、API、資料、權限與錯誤狀態證據必須屬於同一版號或雜湊，不得拼接不同版本的 PASS。任一修改只重驗受影響項目與既定必要回歸。

## 模型

每個新 Goal 在角色首次需要時，以目前主機可用的 OpenAI 通用／代理模型解析並鎖定：

- 主線：目前最新正式通用旗艦的上一個成熟正式世代中，能力最強且適合代理／程式工作的旗艦；High。
- 一般子代理：與主線同世代、定位為平衡／日常／高效率的通用模型；Medium。
- 介面子代理：具備所需瀏覽器、視覺與模態能力者中，以整個工作包預期總成本最低者；Low。
- 新工作包一律從基準推理起跳，不得因預估難度預先派高一檔；太難就拆包。

不用型號字串猜世代，也不在技能中寫死型號。使用者明確指定優先。Goal 續跑／恢復沿用鎖定；僅鎖定缺失、政策變更或模型失效時重解析。技能不能切換已運行的主模型；實際設定不符就揭露差距。派子代理時明確指定鎖定模型與當次推理。

## 驗收與錯誤

主線保留最終 PASS／FAIL。前台驗收由主線提供待驗版本、起始狀態、操作、預期結果、資料／授權邊界與證據要求；介面子代理以真實事件操作並回報 PASS／FAIL／BLOCKED，不改程式、案例或設計風格。

品質錯誤只指代理交付本身錯誤、漏步驟、缺必要證據、誤讀判準或未依指示：

1. 錯 1：主線具體指正，同一鎖定模型升一個受支援推理檔次，重派同一工作包。
2. 錯 2：再次指正、再升一檔、重派同一工作包。
3. 錯 3：停止該工作包的子代理鏈，不作第四次派發；主線接手未完成部分並復用正確成果。

A 查核、B 技術、介面操作各自計數，換代理、改名或恢復對話不清零。視覺代理如實發現成品問題不算它錯，由主線修 A；介面代理如實發現產品 FAIL 不算它錯，退回原 B 技術包。工具、模型容量／路由、權限、來源、逾時或需求變更是執行問題，不計品質錯誤、不升檔，也不得冒充錯 3 讓主線接手技術實作。

子代理不得修改正式規格、操作 Git、對外發送或替使用者拍板；技術子代理只能修改工作包授權的原始碼，未經工作包明列授權不得安裝／移除套件、改 lockfile 或套件管理器、重啟共用服務，migration 等全域編號由主線配發。所有不可逆或敏感操作仍依上層授權規則。

派工、前台案例、模型解析、恢復與證據欄位的操作細節，僅在實際需要時讀 [執行協定](references/execution.md)。
