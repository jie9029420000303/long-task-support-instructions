# 改版流程

這份流程管技能本身怎麼改版，給維護技能的對話看，不會安裝到使用者的技能目錄。依據是 Jay 2026-11-23 的定案：「我想要在實作上引入第一性原理，也就是發生問題或進行功能開發時，應該要以最源頭的根本修改，而不是不斷疊加機制」，以及全域規則第 2B 條「治本不疊補丁」。

## 1 動工前先寫改版提案

每個要改的項目在提案檔寫成一節「## <編號> <標題>」，回答三題：

- 事實最早在哪一步產生：這個問題或功能要處理的事實，最早出現在哪一步。
- 為什麼沒在那一步被記下或擋下：既有機制在那一步為什麼給出錯的結果，或為什麼沒有記下。
- 取代或刪掉哪個既有機制：這次改動取代、合併或刪掉哪些規則、分支、條文或程式。真的只能新增時，寫「只能新增」並在同一句寫明為什麼根因修不了、為什麼不能取代既有機制。

提案檔放在本版的候選資料夾，和發布說明放在一起。

## 2 用工具檢查提案

```
node maintenance/check-proposal.cjs <改版提案.md> --base <上一版 tag>
```

- 任何一項缺題，或第三題空白，結束碼為 1，不得發版。
- 第三題只寫「只能新增」而沒寫原因，同樣不過。
- 加 `--base` 時輸出 `growth`：會安裝到使用者電腦的目錄（與 `install-update.py` 相同：兩個平台的技能、Claude Code 的子代理定義與工作流程）的新增與刪除行數、淨增減、新增與刪除的檔案數。

## 3 發版時列出增減

發布說明照抄檢查結果：每項的三題答案摘要、哪些項目含只能新增的部分（輸出的 `onlyAdds`），以及 `growth` 的數字。淨增加時，說明為什麼這次無法以刪減既有機制達成。
