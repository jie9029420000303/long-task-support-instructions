這一版放寬子代理跟主線同家的限制。OpenCodex 的 plaintextV2AgentMessages 開著時，ChatGPT 訂閱與其他家能互讀子代理的訊息。主線在 Sol 訂閱或 Terra 訂閱上也照子代理順位派工。背景程式每次讀額度時一併確認這個設定，讀到沒開就通知監督，並改回只派 Terra 訂閱。各階的站、門檻 50、35、24、16、10、6、3、1 與換模型步驟都不變。

## A 各角色的換模型順位 {span=2}
訂閱帳號用固定月費和額度。API 按用量計費。高階是 Opus 與 Sol，中階是 Sonnet 與 Terra，開源最後。Opus、Sonnet 是 Claude，Sol、Terra 是 OpenAI，DeepSeek、Muse 走 OpenRouter。

監督與執行主線用同一條順位：
```flow LR
[Opus 訂閱] -> [Opus API] -> [Sol 訂閱] -> [Sol API] -> [Terra 訂閱] -> [Terra API] -> [DeepSeek] -> [Muse]
group 訂閱帳號: Opus 訂閱, Sol 訂閱, Terra 訂閱
group API 按用量計費: Opus API, Sol API, Terra API, DeepSeek, Muse
```

子代理（plaintext 設定開著時，不論主線在哪一家）：
```flow LR
[Sonnet 訂閱] -> [Sonnet API] -> [Terra 訂閱] -> [Terra API] -> [DeepSeek] -> [Muse]
group 訂閱帳號: Sonnet 訂閱, Terra 訂閱
group API 按用量計費: Sonnet API, Terra API, DeepSeek, Muse
```

子代理（plaintext 設定沒開或讀不到，且主線在 Sol 訂閱或 Terra 訂閱時，回到甲選項）：
```flow LR
*[Terra 訂閱]
group 訂閱帳號: Terra 訂閱
```

| 角色 | 推理 | 差別 |
|---|---|---|
| 執行主線 | xhigh | 最優先，額度撞到門檻時留在原站 |
| 監督 | 開案、送驗、結案 xhigh；其他事件 High | 額度撞到門檻時先往下降級 |
| 子代理 | Medium；開源固定 max | ok 主線在哪一家都照子代理順位（原：主線在 ChatGPT 訂閱時只用 Terra 訂閱） |
| 介面操作子代理 | Low | 同子代理順位 |

- 只有訂閱帳號讀得到額度，能事先讓位。API 只在被拒時往下換。
- 監督停在 Terra 或開源時，結案保留到 Opus 或 Sol 回來複驗。
- Claude API 本月額度已用完，12/01 08:00 前所有角色跳過。

## B 降級階梯：低優先的角色先往下讓

|---|---|---|---|---|
| 0 | — | Sonnet・Claude 訂閱 | Opus・Claude 訂閱 | Opus・Claude 訂閱 |
| 1 | 50% | Sonnet・Claude API | — | — |
| 2 | 35% | Terra・OpenAI 訂閱 | — | — |
| 3 | 24% | Terra・OpenAI API | Opus・Claude API | — |
| 4 | 16% | DeepSeek | Sol・OpenAI 訂閱 | — |
| 5 | 10% | Muse | Sol・OpenAI API | Opus・Claude API |
| 6 | 6% | ok Muse（原 Terra・OpenAI 訂閱） | Terra・OpenAI 訂閱 | Sol・OpenAI 訂閱 |
| 7 | 3% | Muse | Terra・OpenAI API | Sol・OpenAI API |
| 8 | 1% | ok Muse（原 Terra・OpenAI 訂閱） | DeepSeek | Terra・OpenAI 訂閱 |

- 目的：讓監督、執行主線與你自己把前段資源用得更久。
- 監督晚子代理兩階，執行主線晚監督兩階。
- 執行主線前面的站被拒時，也會提早落到 Sol 訂閱。Claude API 本月已用完時，第 5 階的主線就直接到 Sol 訂閱，子代理照子代理階梯走，不再固定 Terra 訂閱。
- 可用量＝各訂閱帳號的停用線減週已用，合併 Claude 與能跑 Sol 的 OpenAI 訂閱加權計算。
- 帳號週重置、可用量回升時，階數往回退。

## C 主線派子代理時選哪個模型 {span=2}
```flow
(主線要派子代理) -> {plaintext 設定開著?}
{plaintext 設定開著?} -> *[照子代理順位，從階梯的子代理站起]: 開著（現況）
{plaintext 設定開著?} -> {主線跑在 ChatGPT 訂閱?}: 沒開或讀不到
{主線跑在 ChatGPT 訂閱?} -> 照子代理順位，從階梯的子代理站起: 否
{主線跑在 ChatGPT 訂閱?} -> {Terra 訂閱能用?}: 是：Sol 或 Terra 訂閱
{Terra 訂閱能用?} -> [子代理用 Terra 訂閱，不受子代理階梯限制]: 能
{Terra 訂閱能用?} -> [背景程式把主線換到下一站]: 到停用線或被拒
背景程式把主線換到下一站 -> 照子代理順位，從階梯的子代理站起: 回合結束後
```
- 11/28 00:16 開啟 OpenCodex 的 plaintextV2AgentMessages 並重啟服務後實測，Opus 主線派 Terra 訂閱、Sol 訂閱主線派 DeepSeek，雙方都讀到過程訊息與交件。
- 背景程式每次讀額度時，用 ocx agent status 讀執行中服務的設定。OpenCodex 設定改動或服務重啟後立刻重讀。讀到沒開或讀不到時改回甲選項，並通知監督登記待決帳讓你知道，恢復後再通知一次。
- 這是 OpenCodex 的實驗功能。任務文字會以一般文字留在 Codex 紀錄、各家供應商與本機除錯資料，OpenCodex 或 ChatGPT 改版後可能失效。
- 以下是設定沒開時的情況。「否」包含 Opus 訂閱或 API、Sol API、Terra API、DeepSeek、Muse，這些主線交給子代理的任務沒有加密。

- 11/27 13:58～14:02，Sol 與 Terra 訂閱的主線派 DeepSeek、Muse、OpenAI API 子代理，6 次全被拒。

## D 換模型的步驟與規則 {span=2}
```flow
(背景程式判斷要換模型)
[送切換通知]
[切換生效]
背景程式判斷要換模型 -> {對話閒置?}
對話閒置? -> [下一輪再看]: 回合進行中
對話閒置? -> [即時讀額度，依新讀值重判]: 閒置
即時讀額度，依新讀值重判 -> {試打目標站通?}
試打目標站通? -> [跳過這一站，下一輪取下一站]: 不通
試打目標站通? -> 送切換通知: 通
送切換通知 -> {新回合用哪個模型?}
新回合用哪個模型? -> 切換生效: 新模型
新回合用哪個模型? -> [閒置時重送，最多 3 次]: 舊模型
```
- 切換通知只在對話閒置時送。進行中的回合沿用開始時選定的模型。被拒時回合已經結束，所以立刻送。
- 要送之前，距上次讀額度超過 1 分鐘就即時再讀一次。重置優惠或原廠提前重置會馬上算進去。例行掃描維持每 30 分鐘。
- 你在 OpenCodex 改了停用線、帳號標籤、模型或供應商開關，背景程式下一輪就會發現並立刻重讀，不等 30 分鐘。
- 選站時直接讀 OpenCodex 的模型目錄和設定。主線派工工具只列前 16 個模型，Terra 排在後面看不到，所以不用那份清單。
- 目標站先試打一個極短的請求，串流跑完才算通。不通就跳過，錯誤碼寫明額度、儲值或帳號不支援時記成被拒。試打結果全機共用 1 分鐘，三個工區同時要換只打一次。
- 切換是否生效看新回合實際用的模型。經過多久、請求有沒有失敗都不拿來判斷。
- 換回一律回到角色順位第一站：監督與執行主線是 Opus，子代理是 Sonnet。工區 D 主線因此從 Sonnet 換回 Opus。
- 某一站被拒，該角色往下換一站。每條路線記自己的恢復時間，時間到或之後有成功請求就換回。
- OpenAI 訂閱週已用到停用線 95% 時，所有角色跳過 OpenAI 訂閱，只跳過、不暫停帳號。
- 共用帳號到停用線就暫停。你自己的帳號只讓長任務不算進可用量。
- 同一路線連續 3 次非額度失敗，暫停 30 分鐘並往下換。
- OpenAI API 儲值用完被拒時，所有工區、所有角色共用一份暫停紀錄，5 小時後再試。
- 兩個工區共用一個監督時，只由一個背景程式換它的模型。負責的背景程式 10 分鐘沒動作，另一個才接手。
- 讀 OpenAI 帳號時，prolite 的主欄位和帳號池欄位一律算同一個帳號，不會被重複計算。
- 開源模型暫代監督時照常審查，結案保留到 Sol 或 Opus 回來複驗。
