# Long Task Support Instructions

跨平台長任務協作規則。每個平台各有「長任務監督」與「長任務執行」兩個技能：監督留在研究定案的對話，另一個對話執行並送驗；執行對話以子代理處理可隔離的查核、實作、前台操作或分面研究。

## 使用

1. 在原對話研究、討論並定案目標、授權與驗收條文，然後說「依剛才定案內容啟動長任務監督」。這個原對話就是監督對話，不用手動再開監督對話。
2. 監督保存原始驗收來源、準備執行 prompt，並建立或綁定同平台的另一個**桌面可見**執行對話。Claude Desktop Code 版在沒有原生建對話工具時，由使用者在 App 新對話送出 prompt；背景監看讀到該對話且可喚醒監督後，才能回報「監看已啟動」。Codex 版使用 App 建立對話，也須確認背景監看讀到指定對話才算啟動。
3. 執行對話持續工作；回合結束仍有工作時由本機監看以短訊續接。提問、停滯、派工問題或送驗才喚醒監督對話。監督按原條文逐項查真實候選版，退件就送回同一執行對話修正；全部通過才回報完成。

執行者在工作包變化與等待前更新精簡派工快照；監督查漏派、完成後補派、資源衝突與返工，給具體工作指示，不只增加代理數。新 run 預設啟用；既有 run 的接入方式見各平台技能 runtime。

監看由本機程序等待事件；監督另有自己的進度時鐘：程式每分鐘確認工作有在動、沒超過 AI 時程基準，每 30 分鐘留查核紀錄；只有發現問題（全部靜止、超過基準 1.5 倍或沒有基準、測試程序停住、重複失敗、執行端卡在權限確認、電腦睡眠、真實資源沒用滿）才喚醒模型，不定時投放保活 prompt。Claude 的狀態面板 mod（`claude-code/plugins/lt-status`）另在監督對話中，事件久候 3 分鐘沒有模型回合時送一句短續接，作為喚醒備援。時程基準以模型實測每秒輸出 token 推估，不用人類開發經驗。Claude 的提問、阻塞與送驗先保存事件，再由活躍執行對話送一次桌面原生短訊通知監督，並與背景完成通知去重；送達不明先對帳。現役紀錄曾在記憶體壓力下被 App 暫停；兩端皆暫停或 App 關閉仍無法保證喚醒，不能以隔離成功保證長期可靠。電腦或相應平台停止運作時，不能算即時監看；恢復時先對帳紀錄。原生 Codex Goal 和 Claude `/goal` 都只在使用者明確要求時啟用。

## 結構

- `SPEC.md`：兩個平台共用的行為契約與流程圖。
- `workflow/`：流程圖原始規格與可直接開啟的 HTML。
- `codex/`：Codex 的 `long-task-supervisor` 與 `goal-orchestrator`。
- `claude-code/`：Claude Code 的 `long-task-supervisor` 與 `long-task-orchestrator`；依其實際工具、子代理與模型控制能力適配，不可覆蓋 `codex/`。
- `tests/`：兩版本都必須維持的行為案例。

平台版本只能修改自己的目錄。涉及共同語意時，先變更 `SPEC.md` 與測試案例，再同步調整兩個 adapter。
