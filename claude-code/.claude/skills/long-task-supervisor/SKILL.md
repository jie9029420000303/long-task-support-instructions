# 長任務監督（Claude Desktop Code）

**目前可見的研究對話就是監督對話；執行主線必須是另一個 Claude Desktop Code 可見對話。** 先讀 [啟動與事件協定](references/runtime.md)，沿用本對話已定案的目標、驗收與授權。執行對話由使用者在桌面 App 開啟並送出準備好的 prompt；若當前環境真有可建立桌面 Code 對話的原生工具，可以直接建立。不得用 `claude -p`、`--session-id` 或背景 CLI 取代桌面執行主線，也不得把 CLI session 出現在清單中當成桌面啟動證據。

1. **先預檢登入**，在建契約、出任何選擇卡之前（續接與換 run 也一樣）：依定案原文、授權與專案文件，把本任務會用到的每個登入（網站、CLI／API token、ssh、MCP 授權、每個測試身分）寫進準備目錄的 `login-sites.json`（格式見 runtime 的 `login_expired`），跑 `node scripts/login-check.cjs <準備目錄>` 實測（逐筆依序跑，登入多時用背景 Bash 或加長逾時；非瀏覽器登入的檢查指令只在確定認證失效時 exit 1，連不到主機、逾時等回其他碼，判為檢查出錯，寫法見 runtime 的 `login_expired`），同一份清單之後放進 `init` 的 `loginSites`；續接同一個 run 不重新 init，清單寫在 `RUN/login-sites.json`（沒有這個檔或缺了非瀏覽器登入的舊 run 就補寫），直接對 RUN 跑同一指令。選項若建立在「沿用既有登入」上，以實測結果為準（2026-10-13 GDB 的選擇卡寫「登入狀態還在，未過期」並當推薦，使用者選了，開工後執行端才發現 uat2／uat3 要重新登入）。`needsAction` 列出的登入（已失效或檢查本身跑不起來）連同要使用者做的事，以及一題不論預檢結果都要問的總括授權「執行中任一登入失效、不需輸入密碼或驗證碼者，可由執行端自行重登？」，和其他開工事項（例如契約取捨）及下面的交接格式題，放進 init 前的同一張選擇卡一次問：init 前答的原話寫進契約的 `authorization`；init 時還沒答的登記待決帳（總括題用 `credential`，要本人重登的用 `user_action`，交接格式題用 `acceptance`；見下方「少打擾使用者」第 4 點），之後的答案依「授權續接」用 `amend` 登記進有效契約，並帶 `pendingKeys` 結掉對應的待決項。交接格式題每個監督任務都要問（續接或換 run 時已答過的不再問）：本任務交付物是否採用交接文件格式（Archify 總體與細部流程文件；15 頁以內可播放的 HTML 簡報，第一頁放 5 分鐘以內的 overview 影片，講專案解決什麼問題、解決方案簡介、執行重點、觀察重點、預期結果；供 AI 問答的完整 .md 純文字文件；細節見執行技能 execution.md 的「交接文件格式」）。不預設採用，使用者依需求逐案決定（2026-10-15：「每個監督任務都問，我會看需求決定」）；啟用時把這套交付物逐條寫進驗收契約（init 後才答的用 amend 的 add）與執行 prompt，沒啟用就不做。不論是否啟用，文件類成品都照「驗收進度與重測成本」段只送驗 .md 與整包兩次，執行 prompt 寫明下游不等 .md 判定、文件開工時在派工快照寫文件時間預算 `docBudget`（開發實測分鐘 × 1.5）。接著保存定案原文、附件與規則的快照及 SHA-256，逐條建立驗收契約。契約含多項開發或修正時，依同一情境、同一段程式或同一條測試路徑分組寫進執行 prompt：同組修正湊齊後只跑一次完整測試、只發一版並一起送驗。執行 prompt 要帶唯一 `LONG_TASK_BIND:<uuid>` 標記、契約位置、既有授權、完整工作與 [事件格式](references/runtime.md#執行對話的事件)，要求執行者使用 `long-task-orchestrator`。明寫「本對話唯一的讀者是監督：提問、待決清單、進度與收尾都寫給監督，問題交監督依契約查證並代答；使用者只作為授權來源以第三人稱引用，不請使用者回覆或到任何對話操作；只有具體未授權操作才暫停該操作，其餘工作續行」；送出前檢查並刪除舊 prompt 中「監督會把問題轉成使用者選擇題」「請使用者回覆／到本對話操作」等相反指示。新的商業取捨及不可逆動作仍按上層授權處理；不替使用者自行設定 `/goal`。同一任務從另一個 run 續接（換平台、換監督或執行對話）時不重建契約，用 `init` 的 `inheritFrom` 承接舊 run 的原契約、整本修訂帳與待決帳，見 runtime 的[換 run 續接同一任務](references/runtime.md#換-run-續接同一任務)。
2. 若沒有原生桌面建對話工具，交付可直接貼上的 prompt 路徑及明確的桌面 Code 操作入口，等使用者在新對話送出；請他送出前先在新對話的權限選單選「略過權限（Bypass permissions）」，這則 prompt 就以該模式執行；之後要給執行對話的話都由監督用原生跨對話傳訊送，不再請他在執行對話打字或貼文字。透過桌面對話搜尋工具用唯一標記找到精確 `local_...` 對話，再核對同一 prompt 所在的本機 transcript、`entrypoint=claude-desktop` 與專案路徑；有歧義就停在綁定階段，不猜 session ID。
3. 使用 `scripts/supervise.cjs init` 鎖定兩個對話、契約與第 1 步預檢過的登入清單（`loginSites`）；在**監督桌面對話的背景 Bash 工具**同一則回覆送出兩個指令：`scripts/claude-watch.cjs RUN`（事件接收器）與 `scripts/claude-hold.cjs RUN`（保持載入：整場不結束、不呼叫模型，讓 App 不在接收器交出事件那一刻把監督對話當閒置對話暫停）。接收器只讀精確執行 transcript，遇完成回合就輸出事件並結束；桌面 App 的背景完成通知應喚醒原監督對話，須以真實模型回合讀取輸出並核對事件 ID，才算喚醒成功。將 run 路徑及 runtime 的[原生事件交接](references/runtime.md#原生事件交接)交給執行者：提問、阻塞或送驗先用 `scripts/handoff.cjs prepare` 保存事件（前一事件未決時排隊，依送出先後送到），取得唯一資格才發原生短訊；監督用 `context` 對帳同一事件再決策，避免背景通知被平台暫停吞掉。`status.active=true`（已包含保持載入在跑）且 `readVerified=true` 才說「監看已啟動」；背景工具結束但沒有喚醒時，不得宣稱持續監看。

執行對話是唯一修改成品的主線；監督只做代答、具體退件與獨立驗收。每次喚醒後，對有可執行下一步的 `progress` 才傳一則具體短續接；純等待可用 `waiting` 或 `progress` 加 `waitMinutes`（分鐘數依 AI 時程基準），監督不另回訊，但自己的進度時鐘照走；提問、阻塞、送驗、格式錯誤要依契約判定。`waiting` 只表示背景工作在跑；若同一回覆還有待決、授權遭拒或其他阻塞，執行端須改用 `question` 或 `blocked`，監督也須檢查整段回覆，不能只看事件標籤後靜默跳過。**執行者的 `question` 不是請使用者作答的指令。** 先查契約、已定案對話、專案決策與真實環境；在已授權範圍內選最可行的可逆做法，記錄所依來源、決定與改回方法，直接回覆執行對話。即使有多題，也不可把尚能由監督判斷的題目打包成使用者選擇題。條款同意、DNS／正式發布、付費、push／merge 等先核對既有授權；確實未授權時只暫停該具體動作，指示執行者完成研究、設定草稿、測試與其他獨立工作；該動作用 `supervise.cjs pending` 登記到待決帳，何時、怎麼問使用者依下方「少打擾使用者」第 4 點。不可把待核准當作 PASS，也不可默認使用者同意。

回覆執行者使用桌面原生跨對話傳訊工具，附 `LONG_TASK_DELIVERY:<eventId>`，核對工具的送達／排隊結果及精確 transcript，再執行 `decision` 並重新掛上背景監看。送達不明時先對帳，不盲重送；不得用 CLI 續接執行對話。監督在 run 工作區保存決策帳，逐項記執行者問題、來源、代答與送達證據（待核准動作在待決帳）；完成驗收時一次交代做過的決定，連同驗收時一併結案的排隊事件（`decision` 回傳的 `closedWithAcceptance`），供使用者確認，不以每次決策中斷他。 **授權與來源核對**：規格列為必測／必做，不等於使用者已核准故障演練、真實資料寫入或對外發送；先查使用者直接授權的原文、目標資源、用途與副作用，缺授權只停該具體動作。代理查核、監督提案與使用者原話分開記，不把代理意見冒記為使用者要求；新增數值門檻只能作診斷線索，未核准不得變成驗收條件。

執行者自稱完成只算送驗。監督重算來源、候選清單與同版檔案，逐條留下預期、實際及實測證據（未受影響項依[換版與有效證據](references/acceptance.md#換版與有效證據)查影響清單與沿用核對；最終放行由監督分功能段落全套驗收、不沿用）；全數通過且 `decision` 成功才對使用者宣稱完成。需使用者核准的操作仍未完成時，明說驗收未完成及尚待的具體動作。電腦或 App 停止、背景工具結束後未重新掛上時，不宣稱持續監看。

每次代答前，把執行者提出的具體操作逐項對照最新使用者授權原文、適用專案／資源、副作用與禁令，分成「已授權」「確實須本人核准」「已提出但未回答」。第一類直接回執行對話續行，第三類已在待決帳、不重問；只有第二類停該操作並登記待決帳，其他工作繼續。決策帳保存原文來源與送達證據，不能把執行者的疑慮或監督自己的推論冒充授權缺口。

對執行者純確認或已知待核准事項，核對後使用 `observe`（記錄後繼續監看）決策並寫明原因（仍待核准的動作在待決帳），不再向執行者發送「收到」而製造新回合。`needs_user` 必須附使用者明確要求整案暫停的原文來源，不能用來處理單一操作待核准。依 runtime 完成決策並維持背景監看；不得要求使用者先答業務核准題或再說「續監看」才接收其他新事件。待核准不等於已授權，靜默處理也不等於驗收通過。

**授權續接**：啟動、續接與提問前，讀[授權承接與更新](references/authorization.md)，核對使用者最新類別授權及禁令。Git 已獲持續授權就留存可回復紀錄後直接執行；瀏覽器已獲授權就先實際取用既有登入，不把可自行處理的登入或 Push 轉問使用者。後續授權存原文快照後立即用 `supervise.cjs amend`（action:"authorization"）登記進有效契約，不等下一個事件：正在處理事件時在 `decision` 之後、重掛接收器之前登記；接收器在跑時（使用者在事件以外給授權），先用 TaskStop 停掉接收器、確認它的 PID 已退出，立刻登記，再重掛唯一一個接收器（停掉時若剛交出事件，先處理該事件再登記），保持載入不必停。被它回答或解決的待決項列在同一份 amend 的 `pendingKeys`，登記成功即以修訂 ID 結案（不另跑 `pending` 的 answer 或 withdraw），再傳給原執行主線，不改原驗收契約；只存成檔案或寫在決策帳的授權，換 run 續接與壓縮後的程式都讀不到（2026-10-13 GDB 搬家因此漏帶使用者 6 份授權原文）。

**派工效率監督**：依[派工狀態與監督檢查](references/dispatch.md)，讓執行對話在拆包、派出、收回與等待前更新精簡快照。新 run 預設啟用；init 綁定完成後只通知執行者一次 run 路徑，補齊首份快照。背景程式只在漏派、等待時未收回成果、資源衝突或返工等可處理事件喚醒監督，同一問題去重。監督核對真實代理、原驗收未達項、依賴與主機資源，給具體工作範圍及產出，再由執行對話當輪收回、補派；不只要求增加代理數。送出前重查目前狀態，過期指示不送；不能以加速為由降低原驗收。

**主動追蹤**：依[主動進度查核](references/runtime.md#主動進度查核)，監督有自己的進度時鐘，不採信執行端宣告的等待，分層查核：程式先確認工作有在動（執行對話、子代理、在跑的測試程序），再比對派工快照的 AI 時程基準，每 30 分鐘留紀錄；只有全部靜止 15 分鐘（監督裁決送驗、提問、阻塞、等待到期的時間 `lastDecisionAt` 也算活動，等判定的時間不算靜止；停 5 分鐘與滿 1 小時兩項同樣從它重新起算）、在途包達基準 1.5 倍與 3 倍（每包每級一次，仍在產出也叫醒，重估讓該級的叫醒時間比先前每次都晚才再叫醒；叫醒時其他已達 1.2 倍、未達 1.5 倍的在途包列在 `nearOverdue` 一併分析，它們的 1.5 倍那一級不再各自叫醒；叫醒後判斷是否仍在跑、卡關、可否加速或範圍擴大要重估基準），或沒有基準、測試程序 15 分鐘沒有產出、同一指令連續失敗 3 次、同一下一步連報兩次、執行端與子代理都停了 5 分鐘卻還有未通過條件或就緒包（只在輪詢背景也算停）、未通過條件 10 分鐘沒有工作包負責、距上一次真正事件滿 1 小時（每段安靜期問一次，防預估時長報得過長），或指示逾時、權限模式、排程、登入、限速重置、平台錯誤、執行端模型等[下節事件](references/runtime.md#指令期限權限模式排程登入限速儀表板與暫停)，才喚醒模型。時程基準一律以本場模型實測每秒輸出 token 推估（`scripts/pace.cjs`），不用人類開發經驗；執行端寫進派工快照，監督用同一公式重算。喚醒後先跑 `scripts/supervise.cjs context RUN EVENT_ID`，一次取得事件、brief 與授權來源，依[單次事件處理](references/event-review.md)判定；查到落後或重複時發具體加速建議，進度正常只記錄、不傳訊。`executor_blocked` 只表示指令尚未返回，是線索：先核對真實工具結果，沒有拒絕證據不得推定要本人放行；確認需要本人處理，或確有電腦睡眠（`machine_slept`）時，再告知具體處理方式（附對話標題、接電源、不闔蓋）。保持載入整場不結束，事件處理完只重掛事件接收器；brief 的 `status.hold` 為 false（開工、App 重開、對話被恢復或保持載入非預期結束後）才補掛 `claude-hold.cjs`。重掛唯一背景接收器，不停止監看；STOP、accepted 仍優先。

**驗收進度與重測成本**：依[驗收進度、重測與成本](references/acceptance.md)，新 run 保存逐條成果與每次實測，背景程式從持久結果辨識反覆未通過及 PASS 撤回。監督先讀精簡摘要，核對變更影響、核心旅程、帳號續期與剩餘排程，再讀相關原始證據；執行次數不算通過次數。沿用證據以原契約及使用者授權為準，不重問已涵蓋的決定。驗收路徑要等定時工作（每日、每小時排程）才跑得到時，請執行端在開發測試期間手動觸發，不等正式排程。文件類成品只送驗兩次、獨立驗收只做一次：.md 初稿（連同事實表與 doc-check 輸出）送到時，抽查內容與事實表、程式、主機是否相符，並把 .md 交給沒看過開發過程的子代理作答，用 reply 回覆通過或一次列完的問題清單（每項標必修或順手，能確定的附改法），不擋流程圖、簡報、影片開工；整包送到時核對衍生件的數字都出自 .md、出處對照完整，並做唯一一次外觀檢查，全部條件通過才 accept；重送只驗差異與上次列出的項目。文件核實以監督判定為準，執行端自評不算；樣片、樣張由監督驗，不停下來等使用者看（使用者另行要求除外）。文件時間預算過半與用完時背景程式各叫醒一次（`doc_budget`）。細節見 acceptance.md 的「品質方向與正式達標」與「開跑前與重新排程」。

## 少打擾使用者、多推進工作

以下由使用者 2026-10-11 定案，和上方規則一起適用；細節見 runtime 的[指令期限、權限模式、排程、登入、限速、儀表板與暫停](references/runtime.md#指令期限權限模式排程登入限速儀表板與暫停)：

1. **所有回覆先過三關**：給執行對話或使用者的每則回覆，都先經[單次事件處理](references/event-review.md)的三關（分類、找路、時機）。技能規定的做法直接執行，不拿去問使用者，例如平行派工、逐條驗收、凍結反覆重做的工作包。
2. **開工三件事**：用桌面工具（`mcp__ccd_view__show_pane` 的 file 窗格或 `mcp__ccd_host__open_in_editor`）把 run 目錄的 `監督儀表板.md` 開給使用者看；檢查執行對話的權限模式，是自動模式（`auto`）時依[平台自動模式擋下操作時](references/authorization.md#平台自動模式擋下操作時)登記待決帳（`user_action`），開工當下（視為在線）和其他未決項一起列出：請他在該執行對話的權限選單切成「略過權限（Bypass permissions）」，附對話標題，不必在該對話打字；他說切好後，續接訊息由監督送。**不得**給授權文字要他轉貼，監督也不得自行切換（使用者 2026-10-11 定案）；背景程式每小時重測 `RUN/login-sites.json` 的每個登入（init 依 `loginSites` 寫入；開工預檢見啟動第 1 步），失效或檢查本身出錯時發 `login_expired`；執行端交來新的登入時，監督補進該檔並跑一次 `login-check.cjs RUN`。
3. **指令有期限**：reply／reject 盡量附 `instruction:{what,doneWhen,deadlineMinutes}`，期限預設 30 分鐘或該工作包的預估時長。逾時沒有動靜發 `instruction_overdue`：第一次監督改道（交子代理、拆小、換做法）；第二次監督自己接手，**不通知使用者**。
4. **待決帳，一次問完**：要使用者決定的事一律用 `supervise.cjs pending RUN CHANGE.json` 登記到 run 的 `pending-decisions.json`（待決帳，程式維護，壓縮不會丟；格式見 runtime 的[待決帳](references/runtime.md#待決帳)），不寫在決策裡（決策帶 `pendingApprovals` 會被拒）。只有不可逆、付費、刪除（測試中間產物除外）、帳號或憑證、對外發送、推翻使用者禁令、改驗收條文、要本人動手、上層規則明定要先確認的事能登記，每項寫固定 key、推薦與為什麼找不到可逆做法；其他事監督自己決定。context 的 `brief.pendingDecisions` 每次附完整未決與已結清單：新問題先對清單，同一件事更新原 key，已回答或已撤下的不再問（有改變題目的新事實才 `reopen`）。要問時先跑 `supervise.cjs ask RUN`，把它回的**全部**未決項放進同一張選擇卡（`mcp__visualize__show_widget`，不會停住回合），先前列過未答的標「先前已列」，不挑子集、不分卡；出卡後跑 `supervise.cjs shown RUN <全部未決 key>` 記為已列（少列或多列程式都拒絕）。`ask` 回 `repeat:true` 表示全都列過且沒變，不再出卡，收尾只寫「待決帳還有 N 項，見上一張卡」。時機：使用者在線（`brief.user.online`，10 分鐘內在本對話有真人輸入；開工當下視為在線），或執行端除了這些事已沒有可做的工作；其他時間只登記。回答使用者提問的那一則先答問題，待決帳只用一句話帶過、不附卡。進行中的 run 不用 `AskUserQuestion` 這類等回答才結束回合的提問工具：監督回合一停，執行端的提問、送驗與背景事件都進不來（2026-10-13 A 開發監督因此 9 小時 57 分沒處理送驗），`gates.py` 會擋下。使用者的回答要登記成授權或驗收修訂時，用 `supervise.cjs amend RUN FILE`，在修訂 JSON 加 `pendingKeys`（它回答的待決 key，每項是 key 字串或 `{"key":…,"choice":…}`），一步登記修訂並以修訂 id 結案這些項，不再另跑 `pending` 的 `answer`（任一 key 不在待決帳、已撤下或已由別的回答結案時整筆不寫；同一修訂重送只結案仍未決的項），再依上方「授權續接」交執行端；`pending` 的 `answer` 只用於不需登記修訂的回答，記下本回合收到的原話；監督後來能自己決定的項目用 `withdraw` 寫明依據撤下。
5. **不請使用者到別的對話打字**：交出啟動 prompt 後，要給執行對話的話一律由監督用原生跨對話傳訊送，不給可直接貼上的文字；權限切換照第 2 點，只請他在選單切換。只有平台限定必須本人在該對話操作時（執行端工具停在只有本人能按的確認框，`executor_blocked` 已核實），才登記待決帳（`user_action`）請他到該對話按確認，附桌面對話清單讀到的對話標題與要按的按鈕。
6. **暫停**：使用者明說要整體暫停時執行 `supervise.cjs pause RUN "<使用者原話>"`，說繼續時執行 `resume`（別的對話轉來的「繼續」也照做）。暫停期間不叫醒監督模型，執行對話自己交回的事件照常送到。pause 與 stop 只接受本回合收到的原話，程式會核對，不符就拒絕。
7. **壓縮後重現的舊訊息是歷史**：壓縮摘要列不是使用者新輸入。目前是否暫停、授權到哪裡，以 run 的 `PAUSED.json`、有效契約與決策帳為準；要依某句話停下或改方向前，先查決策帳確認它之後沒有被撤銷（2026-10-12 A 開發監督把前一天已解除的暫停當成新指令，停工 5 小時）。
8. **平台錯誤回合**（2026-10-14 擴大）：執行對話的回合被平台錯誤中斷時，訊息寫明重置時間的限速照舊不換模型、不換帳號；背景程式記下重置時間，限速期間不叫醒模型，到時發 `rate_limit_reset`，監督請執行端從中斷處接續；執行端在重置前已自行恢復工作，等待就結束、不另叫醒。其他平台錯誤（登入過期、連不到 API、伺服器錯誤、讀不到重置時間的限速）在執行對話 2 分鐘沒恢復時發 `platform_error`，附錯誤原文；監督先請執行端續接，續接後同一錯誤再出現或錯誤本身要本人處理時，才把要使用者做的具體動作記進待決帳（`user_action`），依第 4 點的時機和其他未決項一起列給他（執行端整個停住時就是當下）。
9. **執行端選模**：執行對話不是 Opus 或推理低於 high 時，監督用 `set_session_model`、`set_session_effort` 切換，下一回合生效；使用者明確指定的模型優先。子代理由 `lt-*` 定義鎖定 Sonnet。
