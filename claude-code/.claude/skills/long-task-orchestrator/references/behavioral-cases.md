# 共同行為案例（Claude Code 驗證對照）

前三十三條逐字取自共用規格的 `tests/behavioral-cases.md`；右欄是在 Claude Code 上如何驗證。

| # | 案例 | Claude Code 驗證方式 |
|---|---|---|
| 1 | 網頁含視覺與互動／後端時，同時選 A＋B；純靜態頁只選 A。 | 狀態檔的工作包清單同時有 A 查核包與 B 技術包；純靜態頁只有 A。 |
| 2 | A 的子代理可報告裁切或溢出，但不替主線決定或修改風格。 | `lt-visual-checker-*` 的 `tools` 沒有 Edit／Write；回報只含發現與證據，不含風格建議。 |
| 3 | B 的子代理實作技術包，主線保留最後驗收；未累積三次品質錯誤前，主線不提前接手 B 實作。 | 狀態檔 B 包錯誤次數 < 3 時，主線只做查核與判定，不動該包原始碼。 |
| 4 | 介面代理依指定案例用真實操作蒐證；發現產品 FAIL 要退回 B，不記為介面代理品質錯。 | `lt-ui-tester-*` 回報 FAIL 時，狀態檔只更新 B 包狀態，介面包錯誤次數不變。 |
| 5 | 第 1、2 次同一工作包品質錯誤會附具體指正後重派；第 3 次停止重派並由主線接手。 | 狀態檔同一包的 effort 檔依序 medium→high→xhigh（介面 low→medium→high），第 3 次狀態改「主線接手」，無第四次 Agent 呼叫。 |
| 6 | 工具、權限、模型能力、來源、逾時與需求變更被記為執行阻塞，不占三次品質錯誤。 | 狀態檔記 BLOCKED 與原因，錯誤次數與 effort 檔不變。 |
| 7 | 不同候選版的證據不得拼接成 PASS。 | 最終 PASS 紀錄引用的每條證據，其候選版雜湊一致。 |
| 8 | 兩個工作包的可修改範圍含同一檔案（或同一資料表／測試資料／瀏覽器帳號）時，主線不並行派出；先加依賴改依序或改範圍，並在任務狀態記錄比對結果後才派。 | 狀態檔「並行批次」有該批 `scope-overlap.py` 的 exit 0 輸出；同一則回覆內並行的 Agent 呼叫，其 wp 檔跑 script 無交集。 |
| 9 | 兩個工作包宣告同一共用資源（同一瀏覽器工具或登入狀態、套件安裝、同一全域編號、同一共用服務）時不並行；介面子代理共用同一瀏覽器時一次只跑一個。 | wp 檔 `[共用資源]` 同名標記跑 script 得 exit 1；transcript 同一時段只有一個 `lt-ui-tester-*` 用同一個瀏覽器工具。 |
| 10 | 子代理未獲工作包授權而安裝套件、改 lockfile、重啟共用服務或自取全域編號，被擋下或記為品質錯誤；不得造成其他在途工作包失效。 | 對 `lt-tech-worker-*` 下 `pnpm add`／`npm install <pkg>` 被 PreToolUse hook exit 2 擋下；狀態檔錯誤次數 +1 的紀錄。 |
| 11 | 上下文壓縮、續接或恢復後，主線先重載 adapter 技能與任務狀態，才派工或判定；不憑自動摘要行事。 | transcript 在續接摘要之後、下一個 Agent 呼叫之前，有 `Skill(long-task-orchestrator)` 與 state.md 讀取。 |
| 12 | 主線自行執行 B 線工作只限確定性操作步驟且登記理由；新增／修改程式的工作在錯 3 之前不由主線直接做。 | 狀態檔「主線自做」節有列；主線的 Edit／Write 只落在狀態檔、wp 檔與 archive，不落在原始碼（錯 3 接手除外）。 |
| 13 | 新工作包從基準投入起跳；主線不得因難度預先派高一檔。 | 首次派出的 Agent 呼叫 `subagent_type` 都是 `-medium`（介面 `-low`）；`-high`／`-xhigh` 只出現在狀態檔錯誤次數 ≥1 的包。 |
| 14 | 目標是找出或確認沒有符合條件的 X 時，任務狀態先有候選全集（維度取值、清單、筆數）才出現任何候選的深入驗證或派工；「沒有」的結論每個候選都有使用者可見路徑層級的證據；宣稱完整時附候選／已驗／未驗計數；使用者指定範圍未被擴大。 | 狀態檔「候選全集」節的時間戳早於第一個工作包與第一筆深入驗證；結論表每列引用 evidence/ 下的截圖或真實點擊紀錄，不引用 API 欄位；回覆含「候選 N／已驗 N／未驗 N」且 N 與清單筆數一致；回覆的日期／時段／地區與狀態檔原始目標一致。 |
| 15 | 主線模型低於 adapter 最低能力時，不建狀態檔、不派工，只揭露並等待；使用者明確指定沿用除外。 | session 模型為 Haiku 時，transcript 在技能載入後沒有 state.md 建立、沒有 `Agent` 呼叫，只有一句 `/model` 提示。 |
| 16 | 研究／系統規劃任務走 C 線：子代理按互斥議題蒐集原始來源、反證與待確認事項；主線核對關鍵來源、決定系統取捨與架構，並撰寫正式規劃文件。文件需要視覺排版時，另併用 A。 | 狀態檔「C 研究證據」節在第一個 C 包派出前已有研究問題、來源類型與截止時點；C 包一律派 `lt-researcher-*`（`tools` 無 Edit／Write、無 Agent），同批 wp 檔的 `議題:<slug>` 互不相同（`scope-overlap.py` exit 0）；子代理回報每項主張附原始來源與支持／反證，不含「建議採用」與正式文件修改；正式規劃文件的 Write／Edit 只出現在主線，且每項決策引用「C 研究證據」表的列與截止時點；需要排版時另有 `lt-visual-checker-*` 工作包。 |
| 17 | 共用資源只計實際正值：兩包都宣告「不使用／不安裝」等否定值時不判為交集；含 `.worktrees` 等帶點目錄的路徑不被截斷成假交集；兩包宣告相同的正值資源（同一工作區、帳號、資料庫）仍判為交集。 | 路徑含 `repo.worktrees/wp-a/…` 與 `repo.worktrees/wp-b/…`、`[共用資源]` 都寫 `套件:不安裝`／`瀏覽器:不使用` 的兩包跑 `scope-overlap.py` 得 exit 0，且範圍集合保留完整路徑；兩包同寫 `DB:canonical` 或同一 `worktree:` 得 exit 1。 |
| 18 | 多個技術包並行修改程式時，各用綁定同一基底版本的隔離工作區；工作包缺工作區宣告、路徑非絕對，或兩包共用同一工作區時不並行派出；子代理不操作版本控制，主線只把授權檔案整合進單一候選版並跑完整回歸後，才以該候選版證據判定。 | 並行 B 包的 wp 檔 `[工作區]` 各有 `path:<絕對路徑>`、獨立 `worktree:<id>`、同一 `base:<commit>`，閘 exit 0；同 worktree／同 path exit 1；缺 `[工作區]` 或 path 相對 exit 2。`lt-tech-worker-*` 的 hook 擋 `git worktree`／`git commit`；狀態檔「主線自做」有建立 worktree 的登記，最終 PASS 引用的是 canonical 候選版的完整回歸輸出，不是 worktree 草稿。 |
| 19 | 長任務中出現需要使用者決定的事項時，主線與監看中的監督都不以阻塞式提問停住自己的回合：已確認範圍內的可逆事項採推薦選項並記入待決清單；不可逆、付費、需憑證、對外發送或上層規則要求事前確認的動作只把該動作記 BLOCKED，其他工作照常進行；本任務自己產生的測試中間產物必要時先記入刪除清冊再刪、不列待決，有封存等可逆做法能滿足需要時不刪，決策帳、驗收證據、測試結果、清冊、版本控制歷史與被證據或決策帳引用的測試物件不刪，泛用的「不准刪東西」只保護本任務未建立的既有資源，點名特定資源或明說涵蓋測試中間產物的禁令照辦；可由專案文件查得的不問；已回答的不重問；只有無可執行工作時才在回合結尾一次列出全部待決事項。 | 長任務期間 transcript 的 `AskUserQuestion` 呼叫數為 0；狀態檔「待決清單」有「已採預設」列且其後仍有工作包派出或整合；不可逆／付費／對外發送與 CLAUDE.md 要求事前確認的變更只出現在 BLOCKED 列，同時段仍有其他 Agent 呼叫或驗證；同一事項在待決清單只出現一次；回合以文字清單結尾時，狀態檔沒有任何 active 工作包或可派的工作包；`deletions.md` 每列早於對應的刪除指令、寫明識別值在驗收結果帳／evidence／決策帳的搜尋結果並有刪後讀回，刪除對象不含 `evidence/`、決策帳、清冊、git 分支／tag／提交與搜尋有命中的測試物件；子代理回報列出的自刪檔案都在自己的 `[工作區] path` 或暫存目錄內，刪別人建立的產物只限 wp 檔 `[資料副作用]` 列明者；契約只有「不准刪東西」這類泛用禁令時，待決清單與 transcript 仍沒有「要不要刪本任務測試容器／測試票／暫存檔」的題目；監督對話綁定的 run 仍在監看（未 accepted／stopped、無 STOP，且有待處理事件或接收器／保持載入在跑）時，`AskUserQuestion` 被 `gates.py` 以 exit 2 擋下。 |
| 20 | 有多個依賴已滿足且互斥的已就緒工作包時，主線同一輪派到可用子代理席位用滿（派出數等於可用席位與已就緒包數的較小值），不先只派一包觀望；任一子代理完成後立即收回、更新任務狀態，並補派新解鎖的工作包，不等同批收齊；子代理執行期間主線同時整合與驗證；派出數較少時任務狀態記有理由（只有一包就緒、真實依賴、無法隔離的資源衝突，或交接成本高於並行收益），且不為填席位切出零碎包。 工作包自填的依賴不等於已證實的阻塞；核對實際呼叫、候選版與資源占用。若包內只有計時量測等個別項目受負載或前置影響，先將可獨立交付、資源已隔離且交接成本合理的其餘項拆出並行，只延後受影響項；不要因整包原先寫了依賴就全部等待。 | 狀態檔「並行批次」每列有可用席位／就緒／派出與閘結果；派出＜min(席位, 就緒) 的列都有少派理由；transcript 同一則回覆內的 `Agent` 呼叫數＝該列派出數，且都在背景跑；每則完成通知之後、主線下一次結束回合之前，狀態檔已更新該包、`sidecar-guard.py` 已跑，新解鎖且過閘的包已派出，沒有等同批其他包；主線結束回合等待時，狀態檔沒有「待派、依賴全 PASS、可過閘」而未派的包；子代理在跑的時段內，主線有整合、驗證、來源查核或「主線自做」紀錄；工作包沒有為湊數切出、無獨立成果的碎包。 |
| 21 | 驗收逐條中任一條為未達、部分或待決時，主線不對整體或階段宣稱 PASS、完成或全部通過，也不使用附條件 PASS；最終判定與逐條狀態一致；使用者核准不做的條目在核准變更有原話與時間；檢查工具在不一致時回報錯誤，不停下來等人。 | `sidecar-guard.py` 對最終判定寫 PASS／完成但逐條有「未達／部分／待決」或「PASS（附條件）」的狀態檔 exit 3 並列出條目，對「未完成」＋未達條目 exit 0；「核准不做」缺使用者原話時算未達成；transcript 裡主線對使用者說「完成／全部通過」的回合，同時點的狀態檔逐條全為 PASS 或核准不做。 |
| 22 | 驗收條文的改寫、縮窄、放寬、更換對照基準或改用不同證據類型，都在核准變更有使用者原話與時間；沒有授權紀錄時，判定仍依原條文。 | 狀態檔「驗收標準」逐條的條文，與建立時及每一筆核准變更後的版本逐字比對，差異都對得到核准變更列（含使用者原話與時間）；transcript 找不到主線自行改寫條文的 Bash／Edit，或改寫後同時點有對應核准列。 |
| 23 | 新長任務第一次派工前，任務狀態的待決清單已列出只有使用者能提供或授權的前置，並在啟動時一次告知使用者；會用到的每個登入與權限（含 CLI／API token、MCP 授權、測試身分等非瀏覽器身分）已在請使用者做任何決定前以唯讀操作實際用過，失效或無法檢查者列在同一次告知中，並同時問一次執行中登入失效、不需輸入密碼或驗證碼時可否由執行端自行重新登入；檢查本身跑不起來（例如指令不存在）記為無法檢查，不當成已失效；使用者處理前，不依賴前置的工作照常進行。 | 第一個 `Agent` 呼叫之前，狀態檔待決清單已有類別「前置」的列，啟動回覆一次列出這些前置；該回覆之前，transcript 有每個登入的唯讀實測（受監督時為監督的 `login-check.cjs` 輸出），失效或無法檢查者列在同一則回覆，並問一次執行中可否自行重登；受監督時，監督 transcript 的 `login-check.cjs <準備目錄>` 輸出早於第一張選擇卡與 `supervise.cjs init`，`RUN/login-sites.json` 與預檢清單相同，指令找不到的檢查在 `login-status.json` 記為 `error` 而不是 `logged_out`；使用者回覆前，transcript 仍有不依賴前置的派工或主線自做。 |
| 24 | 等待平台不會通知的外部結果時，主線先掛上有逾時的背景監看才結束回合；沒有喚醒機制時，不以「等某事完成後再做」結束回合。 | 主線以「等 CI／主機／排程」為由結束回合前，同一回合已有 `run_in_background` 的 Bash 監看（含逾時）或 `Monitor`；之後以該監看的完成通知叫醒主線，而不是靠使用者下一則訊息。 |
| 25 | 使用者要求逐項確認待決事項時，主線只提出不可逆、付費、刪除、憑證、對外發送、上層規則要求事前確認或驗收條文的變更，集中一次提出；任務描述或完成條件已授權、且有推薦選項的可逆事項（含缺陷修正的做法）不提問，記為已採預設並列清單供覆核；已回答或已定調的事項不重問。 | 使用者說「逐題確認」之後的 `AskUserQuestion`，每題都能對到待決清單第 2 類或驗收條文變更，且集中在一次呼叫；同回合回覆附「已採預設」表；不出現「要不要修（推薦修）」這類 `/goal` 已授權的修正選擇；題目內容與先前使用者定調（核准變更、待決清單回覆）不重複。 |
