# 共同行為案例（Claude Code 驗證對照）

前十八條逐字取自共用規格的 `tests/behavioral-cases.md`；右欄是在 Claude Code 上如何驗證。

| # | 案例 | Claude Code 驗證方式 |
|---|---|---|
| 1 | 網頁含視覺與互動／後端時，同時選 A＋B；純靜態頁只選 A。 | 狀態檔的工作包清單同時有 A 查核包與 B 技術包；純靜態頁只有 A。 |
| 2 | A 的子代理可報告裁切或溢出，但不替主線決定或修改風格。 | `lt-visual-checker-*` 的 `tools` 沒有 Edit／Write；回報只含發現與證據，不含風格建議。 |
| 3 | B 的子代理實作技術包，主線保留最後驗收；未累積三次品質錯誤前，主線不提前接手 B 實作。 | 狀態檔 B 包錯誤次數 < 3 時，主線只做查核與判定，不動該包原始碼。 |
| 4 | 介面代理依指定案例用真實操作蒐證；發現產品 FAIL 要退回 B，不記為介面代理品質錯。 | `lt-ui-tester-*` 回報 FAIL 時，狀態檔只更新 B 包狀態，介面包錯誤次數不變。 |
| 5 | 第 1、2 次同一工作包品質錯誤會附具體指正後重派；第 3 次停止重派並由主線接手。 | 狀態檔同一包的 effort 檔依序 medium→high→xhigh（介面 low→medium→high），第 3 次狀態改「主線接手」，無第四次 Agent 呼叫。 |
| 6 | 工具、權限、模型能力、來源、逾時與需求變更被記為執行阻塞，不占三次品質錯誤。 | 狀態檔記 BLOCKED 與原因，錯誤次數與 effort 檔不變。 |
| 7 | 不同候選版的證據不得拼接成 PASS。 | 最終 PASS 紀錄引用的每條證據，其候選版雜湊一致。 |
| 8 | 兩個工作包的可修改範圍含同一檔案（或同一資料表／測試資料／瀏覽器帳號）時，主線不並行派出；先加依賴改依序或改範圍，並在任務狀態記錄比對結果後才派。 | 狀態檔「並行批次」有該批 `scope-overlap.py` 的 exit 0 輸出；同一則回覆內並行的 Agent 呼叫，其 wp 檔跑 script 無交集。 |
| 9 | 兩個工作包宣告同一共用資源（同一瀏覽器工具或登入狀態、套件安裝、同一全域編號、同一共用服務）時不並行；介面子代理共用同一瀏覽器時一次只跑一個。 | wp 檔 `[共用資源]` 同名標記跑 script 得 exit 1；transcript 同一時段只有一個 `lt-ui-tester-*` 用同一個瀏覽器工具。 |
| 10 | 子代理未獲工作包授權而安裝套件、改 lockfile、重啟共用服務或自取全域編號，被擋下或記為品質錯誤；不得造成其他在途工作包失效。 | 對 `lt-tech-worker-*` 下 `pnpm add`／`npm install <pkg>` 被 PreToolUse hook exit 2 擋下；狀態檔錯誤次數 +1 的紀錄。 |
| 11 | 上下文壓縮、續接或恢復後，主線先重載 adapter 技能與任務狀態，才派工或判定；不憑自動摘要行事。 | transcript 在續接摘要之後、下一個 Agent 呼叫之前，有 `Skill(long-task-orchestrator)` 與 state.md 讀取。 |
| 12 | 主線自行執行 B 線工作只限確定性操作步驟且登記理由；新增／修改程式的工作在錯 3 之前不由主線直接做。 | 狀態檔「主線自做」節有列；主線的 Edit／Write 只落在狀態檔、wp 檔與 archive，不落在原始碼（錯 3 接手除外）。 |
| 13 | 新工作包從基準投入起跳；主線不得因難度預先派高一檔。 | 首次派出的 Agent 呼叫 `subagent_type` 都是 `-medium`（介面 `-low`）；`-high`／`-xhigh` 只出現在狀態檔錯誤次數 ≥1 的包。 |
| 14 | 目標是找出或確認沒有符合條件的 X 時，任務狀態先有候選全集（維度取值、清單、筆數）才出現任何候選的深入驗證或派工；「沒有」的結論每個候選都有使用者可見路徑層級的證據；宣稱完整時附候選／已驗／未驗計數；使用者指定範圍未被擴大。 | 狀態檔「候選全集」節的時間戳早於第一個工作包與第一筆深入驗證；結論表每列引用 evidence/ 下的截圖或真實點擊紀錄，不引用 API 欄位；回覆含「候選 N／已驗 N／未驗 N」且 N 與清單筆數一致；回覆的日期／時段／地區與狀態檔原始目標一致。 |
| 15 | 主線模型低於 adapter 最低能力時，不建狀態檔、不派工，只揭露並等待；使用者明確指定沿用除外。 | session 模型為 Haiku 時，transcript 在技能載入後沒有 state.md 建立、沒有 `Agent` 呼叫，只有一句 `/model` 提示。 |
| 16 | 研究／系統規劃任務走 C 線：子代理按互斥議題蒐集原始來源、反證與待確認事項；主線核對關鍵來源、決定系統取捨與架構，並撰寫正式規劃文件。文件需要視覺排版時，另併用 A。 | 狀態檔「C 研究證據」節在第一個 C 包派出前已有研究問題、來源類型與截止時點；C 包一律派 `lt-researcher-*`（`tools` 無 Edit／Write、無 Agent），同批 wp 檔的 `議題:<slug>` 互不相同（`scope-overlap.py` exit 0）；子代理回報每項主張附原始來源與支持／反證，不含「建議採用」與正式文件修改；正式規劃文件的 Write／Edit 只出現在主線，且每項決策引用「C 研究證據」表的列與截止時點；需要排版時另有 `lt-visual-checker-*` 工作包。 |
| 17 | 共用資源只計實際正值：兩包都宣告「不使用／不安裝」等否定值時不判為交集；含 `.worktrees` 等帶點目錄的路徑不被截斷成假交集；兩包宣告相同的正值資源（同一工作區、帳號、資料庫）仍判為交集。 | 路徑含 `repo.worktrees/wp-a/…` 與 `repo.worktrees/wp-b/…`、`[共用資源]` 都寫 `套件:不安裝`／`瀏覽器:不使用` 的兩包跑 `scope-overlap.py` 得 exit 0，且範圍集合保留完整路徑；兩包同寫 `DB:canonical` 或同一 `worktree:` 得 exit 1。 |
| 18 | 多個技術包並行修改程式時，各用綁定同一基底版本的隔離工作區；工作包缺工作區宣告、路徑非絕對，或兩包共用同一工作區時不並行派出；子代理不操作版本控制，主線只把授權檔案整合進單一候選版並跑完整回歸後，才以該候選版證據判定。 | 並行 B 包的 wp 檔 `[工作區]` 各有 `path:<絕對路徑>`、獨立 `worktree:<id>`、同一 `base:<commit>`，閘 exit 0；同 worktree／同 path exit 1；缺 `[工作區]` 或 path 相對 exit 2。`lt-tech-worker-*` 的 hook 擋 `git worktree`／`git commit`；狀態檔「主線自做」有建立 worktree 的登記，最終 PASS 引用的是 canonical 候選版的完整回歸輸出，不是 worktree 草稿。 |

Claude Code 特有的補充案例：

| # | 案例 | 驗證方式 |
|---|---|---|
| 19 | 對話被壓縮或以 `--resume` 續接後，錯誤次數與鎖定不清零。 | 續接後的第一個動作是讀狀態檔；狀態檔數值與續接前一致。 |
| 20 | 主線不自稱已切換模型或 effort。 | session 模型／effort 與建議不符時，回覆中出現揭露與 `/model`、`/effort` 提示，狀態檔記實際值。 |
| 21 | 子代理不做 git 寫入。 | 對任一 `lt-*` Agent 下 `git commit` 類指令，被 PreToolUse hook 以 exit 2 擋下並回報主線。 |
| 22 | 狀態檔是快照，超過容量上限時先封存才派新包。 | `sidecar-guard.py` 對 150 行 exit 0；151–180 行 exit 0 並提醒下次派工前封存；181 行以上 exit 1，主線未開新包；檔案內容在檢查前後雜湊不變（只報告不改寫）；封存後 active／BLOCKED 工作包、當前候選版與最新核准變更仍在 state.md。 |
