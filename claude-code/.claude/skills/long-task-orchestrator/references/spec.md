# 長任務輔助指令：共用規格

此規格定義平台無關的行為；平台 adapter 只負責把角色、模型與工具映射至可用能力，不能改變本檔的不變量。

```text
任務啟動／續接 → 鎖定目標、候選版、角色配置 → 選 A／B／C 工作線
  A：主線設計與排版 → 子代理客觀視覺查核 ─┐
  B：子代理技術實作 → 必要時子代理真實前台操作 ─┼→ 主線同版整合查核 → 完成
  C：子代理分面研究 → 主線驗證、系統決策與正式規劃 ─┘
                                                   └→ 未達標：判定歸屬 → 重派／第三次主線接手
```

可互動流程圖：[長任務協作流程](https://github.com/jie9029420000303/long-task-support-instructions/blob/main/workflow/long-task-workflow.html)；可審閱原始規格：[workflow JSON](https://github.com/jie9029420000303/long-task-support-instructions/blob/main/workflow/long-task-workflow.json)。

## 不變量

1. 主線保存原始目標、核准變更、驗收、候選版、工作包狀態與最後 PASS／FAIL。
2. A 是視覺／設計工作：主線負責設計、排版、風格判定與修正；子代理只解析來源並客觀檢查裁切、遮擋、溢出、可讀性、對齊、響應式與既定規格，不改成品或判定風格。
3. B 是系統／技術工作：子代理實作前端邏輯、後端、資料整合、修復與必要測試；主線定義驗收、查核證據與最終判定。只有同一技術包累積三次品質錯誤，主線才接手未解實作。主線可自行執行確定性的操作型步驟（執行既有指令、啟動服務、查詢資料），但任何新增／修改程式或資料轉換邏輯的工作都派技術包；主線自做的步驟必須在任務狀態登記項目與理由。
4. C 是研究／系統規劃工作：子代理依可隔離的議題蒐集來源、反證、比較與待確認事項；主線定義研究問題、來源與時點邊界，核對關鍵原始證據，判定系統取捨、架構與驗收，並撰寫正式規劃文件。子代理不得以研究摘要代替主線決策，也不得修改正式文件；需視覺排版時另併用 A。
5. 網頁預設同走 A＋B；僅完全靜態、無互動、無後端的頁面只走 A。
6. 前台驗收由主線提供待驗版本、起始狀態、操作、預期結果、資料／授權邊界與證據要求；介面子代理以真實事件完成操作並回報 PASS、FAIL 或 BLOCKED。
7. 候選版的視覺、互動、API、資料、權限與錯誤狀態須有有效證據才可合併為 PASS；C 的結論須可回溯至同一研究範圍、來源清單與截止時點。換版保存實際變更與影響對照，重驗受影響項目及既定必要回歸；未變依賴的舊證據只能在契約或最新使用者授權允許、且有來源版本與核對紀錄時沿用。契約明定同 commit、完整重驗或連續次數時照原要求；無法判定影響不得自行沿用。
8. 品質錯誤只包括代理交付的錯誤實作、漏步驟、缺必要證據、誤讀判準或未依指示。產品 FAIL、工具／權限／模型／來源／逾時問題與需求變更不計品質錯誤。
9. 每個工作包與工作線分開計數。第 1、2 次品質錯誤：主線具體指正，並在平台支援時提高同一代理的推理投入後重派。第 3 次：停止該包子代理鏈，由主線接手；不得無限重派。新工作包一律從該角色的基準投入起跳，不得因預估難度預先提高；覺得太難就拆包，不升檔。
10. 平台 adapter 在每個新長任務首次需要角色時，依可用且可驗證的能力鎖定主線、一般子代理與介面子代理的模型／投入；續接沿用鎖定。使用者明確指定優先，能力不支援時如實揭露，不偽裝為已套用。
11. 子代理不得自行修改正式規格、進行未授權的不可逆或敏感操作、對外發送，或替使用者做決策；未經工作包明列授權，不得安裝／移除套件、更動 lockfile 或套件管理器、重啟或重建共用服務，也不得自行選用 migration 等全域編號（由主線配發）。
12. 並行只允許可修改範圍與共用資源都互斥的工作包：同一批並行派出的工作包之間、以及與任何在途工作包之間，可修改的檔案／元件、資料表與全域編號、套件與 lockfile、共用服務（開發伺服器、資料庫、測試資料、帳號）、瀏覽器不得有交集。每個工作包必須宣告會觸碰的共用資源；主線每批派出前逐項比對並把結果記入任務狀態；有交集者改為依序（加依賴）或把共用項切給唯一一包。同一個瀏覽器工具或登入狀態同一時間只能由一個介面子代理使用；並行介面測試必須各自使用隔離的瀏覽器。只在禁止事項互相點名、範圍仍重疊，不算隔離。工作區也是共用資源：同一個工作目錄（Git worktree 或非 Git 的工作資料夾）與在其中執行的整體測試，不得由兩個並行工作包共用；多個技術包要並行修改程式時，主線預設為每包建立綁定同一基底版本的隔離工作區，並在工作包與任務狀態記錄其絕對路徑、唯一識別值與基底版本；缺少工作區宣告的工作包不得進入並行比對，也不得猜測其隔離狀態。子代理不得操作版本控制；隔離工作區的成果在主線核對並只把授權檔案整合進單一候選版、跑完整回歸之前只是草稿，不得作為候選版證據。共用資源只宣告實際會讀取、鎖定或改動的項目；「不使用／不安裝／不修改」屬禁止事項，不構成占用，也不能作為隔離證據。
13. 上下文被壓縮、續接或恢復後，主線必須先重新載入本規格的 adapter 技能與任務狀態，才可再派工或判定；自動產生的對話摘要不是規則或狀態的來源。
14. 目標為「找出符合條件的 X」或「確認沒有 X」時，主線在深入任一候選或派工前，先在任務狀態枚舉搜尋空間：每個條件維度的取值與來源、展開後的候選清單與筆數。每個候選以同一判準驗證；「不可行／沒有」只能以使用者可見路徑層級的證據（真實操作到底）判定，內部欄位、API 旗標、DOM 狀態只作線索。宣稱完整、窮舉或全部時必附候選、已驗、未驗計數與未驗原因，數字不符不得宣稱。使用者指定的範圍（日期、時段、地區等）不得為了得到結果而自行擴大。
15. 平台 adapter 判定主線模型低於該平台定義的最低能力時，不建立任務狀態、不派工、不判定，只揭露差距並等待使用者切換；使用者明確指定沿用者除外。
16. 長任務執行中，主線不得以會阻塞整條主線的方式向使用者提問（例如須等回答才能繼續的互動提問工具）。需要使用者決定的事項依類別處理：在已確認範圍內、可逆且主線已有推薦選項者，採推薦選項繼續，並在任務狀態的待決清單記下已採選項與改回方式；不可逆、付費、刪除、登入／憑證、對外發送，或上層規則明定必須事前確認的重大內容／設計變更，只把該單一動作記為 BLOCKED 並附推薦方案，其餘已授權工作照常進行；先核對既有授權，已涵蓋且平台允許預先授權者直接做，其餘才須取得使用者確認；答案可由專案文件、規格、操作手冊或既有決策查得者，先查不問；使用者已回答的問題不得重問，回答不明確時採最接近的可逆解讀並記入待決清單。只有在沒有任何可執行工作時，主線才在回合結尾一次列出全部待決事項、推薦選項與後果後停下。任務描述或長任務完成條件已授權的工作（例如「發現缺陷就修復並上線」），其做法選擇若在已確認範圍內、可逆且主線有推薦選項，即屬前述可逆事項，不向使用者提問。使用者要求逐項確認待決事項時，只提出不可逆、付費、刪除、登入／憑證、對外發送、上層規則明定須事前確認的變更與驗收條文的變更，集中一次提出，不另增題目；已採預設的事項列成清單供使用者覆核。提問前先查任務狀態的待決清單與核准變更，已有答案或已定調的不再問；每個提問須能單獨看懂並附具體實例。
17. 積極派工（可派即派、不留空席）：主線每次派工前，找出所有依賴已滿足、不等使用者授權的已就緒工作包，連同全部在途工作包依不變量 12 比對；無交集者依「先完成會解鎖最多後續工作」排序，同一輪派到平台當下可用的子代理席位用滿。不得先只派一包觀望，除非該包的結果會改寫其他包的範圍或判準。任一子代理完成時，主線立即收回、核對並更新任務狀態，把新解鎖的工作包連同仍在途者重新比對後補派，不等同批其他包收齊。子代理執行期間，主線同時進行整合、直接來源查核、確定性操作、驗證與下一批準備；只有這些都沒有、且所有已就緒包都已在途時才等待。不為填滿席位切出沒有可獨立交付成果、或交接與驗收成本高於代理工作本身的零碎包。只派一包，或派出數少於可用席位與已就緒包數兩者的較小值時，任務狀態必須記錄理由：只有一包就緒、其他包依賴這包的結果（含其結果會改寫其他包的範圍或判準）、無法隔離的共用資源衝突，或交接／驗收成本高於並行收益。積極派工不放寬不變量 7、9、11、12、16 與上層授權規則。 受監督的執行對話在工作包狀態變化與等待前原子更新精簡派工快照。監督背景程序只在漏派、等待時有未收回成果、排他資源衝突、明示返工或實測結果帳顯示同案例反覆未通過／PASS 撤回等可處理問題時發出事件，持久去重；監督核對真實代理、原驗收未達項、依賴與資源後給具體工作指示，由執行對話收回並補派。快照不等於平台事實或驗收證據；同一狀態不反覆催促，送前重查、過期指示不送，問題解決後再發生須用新事件識別，不能沿用舊決策。 工作包自填的依賴不等於已證實的阻塞；核對實際呼叫、候選版與資源占用。若包內只有計時量測等個別項目受負載或前置影響，先將可獨立交付、資源已隔離且交接成本合理的其餘項拆出並行，只延後受影響項；不要因整包原先寫了依賴就全部等待。
18. 驗收逐條與放行紀律：任務狀態逐條保存鎖定的驗收條文與各條的狀態（PASS、未達、部分、待決、使用者核准不做）、證據與候選版。任一條不是 PASS 或使用者核准不做時，主線不得對整體或階段宣稱 PASS、完成、達成或全部通過，也不得以「附條件 PASS」等說法放行，只能回報進度與剩餘條目；使用者核准不做的條目須在核准變更記錄使用者原話與時間。平台 adapter 須提供在每次派工前與判定後執行的檢查：列出驗收逐條，並在最終判定與逐條狀態不一致時回報錯誤交主線修正；此檢查不得以等待使用者確認的方式阻塞。
19. 驗收條文只能依使用者明確授權變更：主線改寫、縮窄或放寬條文，更換對照基準，或以單元測試、本機結果、較少輪次等不同證據替代條文要求者，都屬變更，須先在核准變更記錄使用者原話與時間；未獲授權的變更無效，原條文照舊適用。不變量 16 的「採推薦選項繼續」與「採最接近的可逆解讀」不適用於驗收條文的變更。
20. 開工前置盤點：新長任務在第一次派工前，主線盤點完成目標所必需、只有使用者能提供或授權的前置（權限、帳號與憑證、付費或資源開通、主機與網域、不可逆或對外操作的授權、需使用者拍板的取捨），寫入任務狀態的待決清單並在啟動時一次列出；列出後不等待回答，先進行不依賴這些前置的工作。執行中才發現的前置依不變量 16 處理。
21. 外部等待須有喚醒：主線等待平台不會主動通知的外部結果（CI、遠端排程、主機或外部系統上的長程序）時，須先掛上會在結果出現或逾時時喚醒主線的背景監看，才可結束回合；不得在沒有喚醒機制時以「等某事完成後再做」結束回合。監看由背景程序以有界間隔查核，並有逾時與失敗回報，不由主線回合忙輪詢。
22. 發布授權逐項核對：任務狀態保存本次 merge、push、PR 合併、tag、Release、部署等各項操作的使用者授權原話與時間、儲存庫、來源與目標分支或環境、允許的候選變更範圍與放行條件。只在操作前核對實際分支、候選提交、目標與條件；已獲明確授權且完全符合者直接執行，不再要求相同確認。未授權、新增操作、範圍或目標變更、放行條件未過者只停該操作，先完成其餘已授權工作，再一次提出可審查的具體差異；已提出而尚未回答的同一核准題不重提。一般「完成上線」意圖不自動涵蓋未明示的 Git 或發布操作；依使用者明示的適用範圍與期間判斷：單次候選授權不自動延伸，明示的本任務持續授權可涵蓋後續修正版，不得再次逐筆索取同一授權。後續授權另存原文、來源、時間與禁令，保留原驗收契約，更新監督與執行的授權表及已解鎖待辦。已授權的 Git 操作留下操作前後與可回復版本；已授權的瀏覽器登入先實際取用既有登入與既有權限，不以推測要求使用者重登入；禁止刪除與付費需確認等明示邊界依原文保留。單一操作待核准不是整個長任務的故障，整體 blocked 依平台 Goal 狀態規則判定。
23. 監督與執行分離：使用者在研究對話定案後啟動監督時，該對話承接已定案目標、來源、授權與逐條驗收；監督建立或精確綁定另一個執行對話，交付可直接執行的 prompt。執行對話沿用本規格的派工與自查，是唯一修改成品的主線；監督只做代答、退件與獨立驗收，不與執行者同時修改成品。監督啟動不自行建立 Codex 原生 Goal 或代使用者設定 Claude `/goal`。
24. 驗收契約與同版送驗：監督鎖定原始來源快照及其雜湊，逐條保存驗收條文、來源與查核方法；未經使用者授權不得縮窄或改寫。執行者每次送驗產生候選清單與雜湊，包含本次直接修改的交付檔。監督重算來源、清單及候選檔，對每條有效條文留下當前候選的有效證據及允許的沿用核對；使用者後續修訂另存有原文、定位、時間與雜湊的不可改寫帳本，原契約保留。監督、執行與放行都讀同一有效範圍，核准移出的項目明列 EXCLUDED，不能算 PASS；任一條未通過就具體退件，不能因執行者自述或部分 PASS 宣稱完成。候選檔變動後須重新送驗。
25. 事件驅動續接：監督在本機以背景程序等待綁定對話的完成回合及決策事件；平常讀取不喚醒模型，不以排程反覆貼長 prompt。執行回合結束時送出進度與具體下一步、提問、阻塞或候選版事件；可續做的進度由背景程序短訊續接，停滯、提問、送驗、異常、意外結束及監督自己的進度時鐘才喚醒監督。監督的進度時鐘不以執行端宣告的等待為準：至少每 30 分鐘查一次進度（只有監督自己核實並保存的等待——等使用者核准或外部結果——可暫停），在途工作包超過 AI 時程基準 1.5 倍、同一失敗指令重複 3 次或同一下一步連報兩次即查；落後或重複時在授權範圍內給具體加速建議，進度正常只記錄、不傳訊。時程基準、等待時間與完成估計一律以 AI 實測速度推估：預估輸出 token ÷ 本場同模型實測每秒輸出 token，加上已量測的工具時間，不用人類開發經驗；執行端把基準寫進派工快照，監督以同一公式重算覆核。訊息以唯一標記送出並讀回確認；送達不明先對帳，不盲目重送。背景程序或平台停止時，狀態不得假稱仍在即時監看；恢復時從已保存的游標、收件與決策續接；saved inflight 的延遲收件只讀對帳，不重送，STOP 與已完成仍優先。 對純確認或已記錄的待核准事項，監督可記錄具體原因及仍待核准動作，靜默處理該事件後繼續接收新事件；不為了繼續監看傳送無必要回覆，也不把單一待核准動作變成停止監看。靜默處理不代表授權或驗收通過；使用者明確停止仍優先。15 分鐘查核核對後若只剩未變等待，可保存具體條件靜默監看；新授權／執行事件、條件檔或已有期限變動再查核，不反覆喚模型，也不停止接收。候選否決不自動撤回持續代判授權，重做依最新意圖判斷。
26. 放行界線：只有監督對原契約加有來源的使用者修訂形成的有效條文逐條作出有證據的 PASS，並通過同版決策檢查，才可回報整體完成。新的商業取捨、不可逆或其他未授權動作按上層確認規則處理；只擋該動作，其餘已授權工作續行。執行者回報完成只視為送驗，監督未放行前不可對使用者宣稱整體達標。
27. 執行期資源收尾：主線或子代理啟動、會在當下回合或工作包結束後繼續存活的執行期資源（開發伺服器、預覽伺服器、容器與 compose 專案、其他常駐程序），啟動時即登記於任務狀態的資源帳本：所屬工作包、可核對的識別（程序與其啟動時間、埠、容器或 compose 專案名）、啟動指令與工作目錄、關閉時點。關閉時點預設為所屬工作包判定之後；主線自用的服務在宣稱完成前關閉；只有要交使用者驗收的最終候選版預覽可保留至使用者驗收，須寫明理由並設到期自動關閉的期限；確定不屬本任務的資源只登記、不關閉，須寫明歸屬。等待迴圈與背景監看一律設逾時。工作包判定後，主線關閉該包的資源並核對確已停止。平台 adapter 須提供在每次派工前與判定後執行的檢查：以實際程序與容器狀態核對帳本，並掃描任務開始後出現在本任務工作區內、已脫離對話卻未登記的常駐程序與容器；已判定工作包的資源仍在執行、宣稱完成時仍有未保留的資源在執行、保留或歸屬缺理由，或有未登記資源時，回報錯誤交主線處理，不以等待使用者確認的方式阻塞。檢查只報告、不自動關閉；關閉只作用於帳本內且身分核對相符的資源，不屬本任務者（開機常駐服務、任務開始前已在執行的服務、其他任務登記的資源）不得關閉。

## 平台適配界線

- `codex/`、`claude-code/` 各自包含監督與執行兩個技能，並管理觸發方式、長任務機制、模型與推理控制、子代理工具、安裝位置及平台限制。
- Adapter 可加上平台特有的安全規則，不能放寬本規格。
- 如果平台不支援某項模型或子代理控制，adapter 必須採最接近且可驗證的替代方式，並揭露差距。
