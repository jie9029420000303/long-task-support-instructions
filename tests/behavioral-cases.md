# 共同行為案例

每個平台 adapter 更新後，至少應驗證以下案例。

1. 網頁含視覺與互動／後端時，同時選 A＋B；純靜態頁只選 A。
2. A 的子代理可報告裁切或溢出，但不替主線決定或修改風格。
3. B 的子代理實作技術包，主線保留最後驗收；未累積三次品質錯誤前，主線不提前接手 B 實作。
4. 介面代理依指定案例用真實操作蒐證；發現產品 FAIL 要退回 B，不記為介面代理品質錯。
5. 第 1、2 次同一工作包品質錯誤會附具體指正後重派；第 3 次停止重派並由主線接手。
6. 工具、權限、模型能力、來源、逾時與需求變更被記為執行阻塞，不占三次品質錯誤。
7. 不同候選版的證據不得拼接成 PASS。
8. 兩個工作包的可修改範圍含同一檔案（或同一資料表／測試資料／瀏覽器帳號）時，主線不並行派出；先加依賴改依序或改範圍，並在任務狀態記錄比對結果後才派。
9. 兩個工作包宣告同一共用資源（同一瀏覽器工具或登入狀態、套件安裝、同一全域編號、同一共用服務）時不並行；介面子代理共用同一瀏覽器時一次只跑一個。
10. 子代理未獲工作包授權而安裝套件、改 lockfile、重啟共用服務或自取全域編號，被擋下或記為品質錯誤；不得造成其他在途工作包失效。
11. 上下文壓縮、續接或恢復後，主線先重載 adapter 技能與任務狀態，才派工或判定；不憑自動摘要行事。
12. 主線自行執行 B 線工作只限確定性操作步驟且登記理由；新增／修改程式的工作在錯 3 之前不由主線直接做。
13. 新工作包從基準投入起跳；主線不得因難度預先派高一檔。
14. 目標是找出或確認沒有符合條件的 X 時，任務狀態先有候選全集（維度取值、清單、筆數）才出現任何候選的深入驗證或派工；「沒有」的結論每個候選都有使用者可見路徑層級的證據；宣稱完整時附候選／已驗／未驗計數；使用者指定範圍未被擴大。
15. 主線模型低於 adapter 最低能力時，不建狀態檔、不派工，只揭露並等待；使用者明確指定沿用除外。
16. 研究／系統規劃任務走 C 線：子代理按互斥議題蒐集原始來源、反證與待確認事項；主線核對關鍵來源、決定系統取捨與架構，並撰寫正式規劃文件。文件需要視覺排版時，另併用 A。
17. 共用資源只計實際正值：兩包都宣告「不使用／不安裝」等否定值時不判為交集；含 `.worktrees` 等帶點目錄的路徑不被截斷成假交集；兩包宣告相同的正值資源（同一工作區、帳號、資料庫）仍判為交集。
18. 多個技術包並行修改程式時，各用綁定同一基底版本的隔離工作區；工作包缺工作區宣告、路徑非絕對，或兩包共用同一工作區時不並行派出；子代理不操作版本控制，主線只把授權檔案整合進單一候選版並跑完整回歸後，才以該候選版證據判定。
19. 長任務中出現需要使用者決定的事項時，主線與監看中的監督都不以阻塞式提問停住自己的回合：已確認範圍內的可逆事項採推薦選項並記入待決清單；不可逆、付費、需憑證、對外發送或上層規則要求事前確認的動作只把該動作記 BLOCKED，其他工作照常進行；本任務自己產生的測試中間產物必要時先記入刪除清冊再刪、不列待決，有封存等可逆做法能滿足需要時不刪，決策帳、驗收證據、測試結果、清冊、版本控制歷史與被證據或決策帳引用的測試物件不刪，泛用的「不准刪東西」只保護本任務未建立的既有資源，點名特定資源或明說涵蓋測試中間產物的禁令照辦；可由專案文件查得的不問；已回答的不重問；只有無可執行工作時才在回合結尾一次列出全部待決事項。
20. 有多個依賴已滿足且互斥的已就緒工作包時，主線同一輪派到可用子代理席位用滿（派出數等於可用席位與已就緒包數的較小值），不先只派一包觀望；任一子代理完成後立即收回、更新任務狀態，並補派新解鎖的工作包，不等同批收齊；子代理執行期間主線同時整合與驗證；派出數較少時任務狀態記有理由（只有一包就緒、真實依賴、無法隔離的資源衝突，或交接成本高於並行收益），且不為填席位切出零碎包。 工作包自填的依賴不等於已證實的阻塞；核對實際呼叫、候選版與資源占用。若包內只有計時量測等個別項目受負載或前置影響，先將可獨立交付、資源已隔離且交接成本合理的其餘項拆出並行，只延後受影響項；不要因整包原先寫了依賴就全部等待。
21. 驗收逐條中任一條為未達、部分或待決時，主線不對整體或階段宣稱 PASS、完成或全部通過，也不使用附條件 PASS；最終判定與逐條狀態一致；使用者核准不做的條目在核准變更有原話與時間；檢查工具在不一致時回報錯誤，不停下來等人。
22. 驗收條文的改寫、縮窄、放寬、更換對照基準或改用不同證據類型，都在核准變更有使用者原話與時間；沒有授權紀錄時，判定仍依原條文。
23. 新長任務第一次派工前，任務狀態的待決清單已列出只有使用者能提供或授權的前置，並在啟動時一次告知使用者；會用到的每個登入與權限（含 CLI／API token、MCP 授權、測試身分等非瀏覽器身分）已在請使用者做任何決定前以唯讀操作實際用過，失效或無法檢查者列在同一次告知中，並同時問一次執行中登入失效、不需輸入密碼或驗證碼時可否由執行端自行重新登入；檢查本身跑不起來（例如指令不存在）記為無法檢查，不當成已失效；使用者處理前，不依賴前置的工作照常進行。
24. 等待平台不會通知的外部結果時，主線先掛上有逾時的背景監看才結束回合；沒有喚醒機制時，不以「等某事完成後再做」結束回合。
25. 使用者要求逐項確認待決事項時，主線只提出不可逆、付費、刪除、憑證、對外發送、上層規則要求事前確認或驗收條文的變更，集中一次提出；任務描述或完成條件已授權、且有推薦選項的可逆事項（含缺陷修正的做法）不提問，記為已採預設並列清單供覆核；已回答或已定調的事項不重問。
26. 本次長任務已明確授權的發布動作，狀態檔逐項保存使用者原話、時間、儲存庫、分支／環境、允許變更範圍與放行條件；實際候選版符合時直接執行、不重問。未授權、目標或變更範圍改變時，只停該動作並提出可審查的具體差異；先前已提出而未回答的核准題不在續接時重提。
27. 工作包判定後，該包啟動的開發伺服器、預覽與容器已關閉並核對停止；只有要交使用者驗收的最終候選版預覽標記保留，並有理由與到期期限；等待迴圈都有逾時；已判定工作包仍有資源在跑、宣稱完成時仍有未保留的資源在跑，或出現未登記的脫離程序／容器時，檢查工具回報錯誤交主線處理、不停下來等人；開機常駐服務、任務開始前的服務與其他任務的資源不被列入或關閉。
28. 受監督時，需要使用者決定的事項登記在 run 目錄的待決帳：類別不在可登記範圍的事項被拒、由監督自行決定；原樣重登同一項不算變動；已回答或已撤下的同一事項，不論沿用原識別或換識別用同一段文字，沒有記明新事實就不能再提問；壓縮後監督每次喚醒讀取的內容仍附完整未決清單；監督只在使用者在線或執行端已無其他可做工作時提問，一次列出全部未決項，提出時列的不是全部未決項就不記為已提出；沒有新項或變動時不重列。
29. 受監督的執行回合被平台錯誤中斷時：寫明重置時間的限速是已知等待，不換帳號、未經使用者授權不換模型、不請使用者處理，等到重置時間或執行端自行恢復，執行端已自行恢復就不再為這筆限速叫醒監督；其他平台錯誤（含讀不到重置時間的限速）2 分鐘（扣掉電腦睡眠）未恢復才叫醒監督一次並附錯誤原文，監督先請執行端從中斷處接續，同一錯誤再出現或須本人處理時才告訴使用者具體動作；子代理的非限速平台錯誤由執行端重派。
30. 監督換平台或換對話續接同一任務時，新 run 原樣承接舊 run 的原契約、整本修訂／授權帳與待決帳：有效契約雜湊與舊 run 相同，每筆使用者原文快照雜湊相符；任一來源遺失、變動或舊 run 監看仍在跑就拒絕，不建新 run 目錄，舊 run 檔案不變。舊 run 只存成檔案、未登記的授權先在新 run 補登，才通知執行者續做；監看在跑時收到的新授權當下登記，不等下一個事件；已授權事項不轉問使用者。
31. 受監督的執行對話把提問、待決清單、進度與收尾寫給監督，需要決定的事以提問或阻塞事件交監督，不請使用者回覆、到任何對話操作或轉貼授權；監督交出啟動 prompt 後也不請使用者到任何對話打字或貼文字，不自行切換執行對話的權限模式，需要切換時只請使用者在該對話的選單切換，續接訊息由監督送。前一事件尚未處理完時再送的提問、阻塞或送驗會排隊並依送出先後送到監督，執行對話不收到錯誤、照常續做其他工作；佇列裡有較新的送驗時監督不接受目前候選版，只有提問或阻塞排隊時驗收照常，這些排隊事件驗收時一併結案並列入給使用者的收尾清單。
32. 受監督時，在途工作包經過時間（扣掉電腦睡眠）達時程基準 1.5 倍與 3 倍時各叫醒監督最多一次，即使仍在產出或仍有程序在跑；同一工作包換新階段或範圍擴大時，主線當下重估並寫入新的時程基準（新的開始時間與分鐘數），不沿用前一階段的基準，監督的進度時鐘把重估後的基準當新基準，重新計算 1.5 倍與 3 倍。
33. 同一情境、同一段程式或同一條測試路徑的多個待修項目分在同一組一起修；實作工作包的判準只列定向測試，也只跑定向測試；主線把同組成果整合成單一候選版，該候選版只跑一輪完整測試，通過才發版、部署或送驗，完整測試次數不超過整合組數加上失敗後的重跑輪數（契約要求的連續次數另計）；完整測試失敗時，該輪失敗全部歸因、一起修正後才重跑，不修一項跑一次；同組新出現的項目在該組開測前併入，開測後排入下一組；契約要求全套、同 commit 或連續次數時照原要求。
